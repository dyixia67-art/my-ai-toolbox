## 一句话主线

今天是**"助手长进系统、模型身份要能自证、agent 已成最大客户"**的一天：苹果同一天把两条线推到台前——Siri AI 向所有开发者开放（连"skills"都用了 SKILL.md 的写法）、中国版 Apple Intelligence 进开发者测试（底座是 Qwen）；腾讯 Hy4 则把"看得见、能操作电脑"做进开放权重旗舰，却和 Kimi 一样先给网络安全能力踩了刹车；而 Anthropic 的 FlashProve 与四家大厂共推的训练 opt-out 信号，一前一后在回答同一个问题：agent 时代，**怎么证明一个输出真是某个模型做的、一份内容有没有同意被拿去训练**。

### 1. Siri AI Developer Preview（苹果，11 月 3 日）——所有 App 都能往 Siri 里插动作，还能用 SKILL.md 教它串活
- **含义**：iOS 27.3 / iPadOS 27.3 / macOS 27.3 / watchOS 27.3 / visionOS 27.3 首个开发者测试版里，Siri AI 不再只接少数有现成 schema 的 App：任何开发者都可以用已有的 App Intents 框架，把自己 App 的动作与内容暴露给 Siri AI；Siri AI 能识别的实体也不再限于有 schema 的那批，而是 Spotlight 索引到的任何实体。苹果同时新推了 **skills**：开发者用 SKILL.md 文本文件描述"几个动作怎么拼成一次完整体验"，让 Siri AI 处理多步复杂请求。
- **与你直接相关的两点**：① 这个"skills"和你 Codex 团队里的 Skills 是同一种形态——一份教 agent 怎么组合动作的文本说明，只是宿主从 Claude Code / Codex 换成了 Siri；你给 Codex 角色写 SKILL.md 的经验（写清触发条件、步骤、边界）可以直接平移到这里。② 苹果自己先划了线：skills"不能用来强制确定性行为"——即它只能"教 Siri 怎么串"，不能保证每次都按固定流程走；给 agent 排活时，这句话值得抄下来贴在所有"多步串联"任务的验收标准旁。
- **时间线（别把预览当上线）**：现在只是 Developer Preview，仅限开发者自己跑的构建与内部 TestFlight 测试者，外部测试者与 App Store 版都拿不到；苹果称面向用户"几个月后"，App Store 提交带 Siri AI 集成的应用要到 2027 年春。另有三条硬限制：欧盟地区 iOS / iPadOS / watchOS 上 Siri AI 仍不可用；13 岁以下用户不可用；依赖服务端模型的功能（含 Siri AI）有每日用量上限，未来预计有付费扩容档。语言：首发英、法、日、韩、葡、西六种，繁体中文、挪威语、土耳其语、越南语随后加入；苹果自家 15 个 App（日历、文件、访达、日志、邮件、地图、信息、音乐、备忘录、照片、预览、提醒事项、Safari、快捷指令、天气）也在本轮拿到新的 Siri AI 动作。
- **为什么出圈**：这是 Siri 从"苹果自家助手"变成"系统级 agent 入口"的关键一步——以前是苹果挑 App，现在是所有 App 都能来报名；且"skills"这个词从编码 agent 圈正式进入手机系统层。结合今天中国版测试（下条），同一天里"助手长进系统"在开发者侧与区域侧同时落地。

### 3. 腾讯 Hy4（11 月 4 日正式版）——开放权重旗舰第一次"看得见、能操作电脑"，权重却还没放出

### 4. 新词：`__usage_ai-training`（IETF AIPREF 草案）——四家大厂共推的"训练 opt-out 通用信号"
- **含义**：网站主在 `robots.txt` 里写一次，即可表达"不希望内容被用于 AI 训练"的偏好，不必再给每家爬虫各写一套规则。机制来自 IETF AI Preferences（AIPREF）工作组草案《Machine-Readable Training Preference Signal》（10 月 30 日更新的 draft-kelley-aipref-training-preference-signal-00，作者为 Anthropic 标准负责人 Kevin Kelley），核心是一个策略 token：`__usage_ai-training`，可作用于整站或指定路径，仍沿用 `robots.txt` 框架。
- **四家进度不同，别写成"已统一生效"**：Anthropic 已实现（其爬虫须遵守该信号）；OpenAI 承诺"未来几个月内"实现，目前只是承诺；Google 计划 2027 年随标准推进而支持，并称若网站只写通用 opt-out 而未单独写 Google-Extended，将按 Google-Extended 禁止理解；微软定出四个日期：2026 年 12 月 15 日在 Bing Webmaster Tools 开过渡设置、2027 年 2 月 1 日起按新信号执行、2027 年 3 月 1 日为旧 NoArchive / NoCache 信号迁移截止、2027 年 9 月 30 日临时 grounding 设置到期。
- **关键区分（最容易被标题带偏处）**：这支信号管的是**训练偏好**，不是"不被 AI 引用/回答"——网站主写了它，不等于内容就不会出现在 AI 生成的答案里；且草案仍是 Internet-Draft，不是已定标准，技术形态与各家实现在全面铺开前都可能变。你自己的内容若在意训练用途，现在能做的是先记下这个 token 与各家时间表，等 2027 年各家实现落地后再按"写一次"的方式部署，而不是今天就以为写上即生效。
- **为什么出圈**：这是 10 月日报"agent 从连上走向管住"在内容侧的对应物——前面管的是 agent 能碰什么（OpenShell 的 runtime 策略）、协作怎么管（Atlassian AMP），今天管的是" agent 背后的训练数据从哪来、主人同不同意"。四家平时互为对手的厂商在同一份草案上对齐，本身就是信号。
- 出处：https://www.mlllm.io/articles/3667-openai-google-microsoft-and-anthropic-back-unified-ai-scraping-opt-out-signal-in-robots-txt/ · https://dev.clauneck.workers.dev/alifar/google-microsoft-openai-and-anthropic-back-a-shared-ai-training-opt-out-signal-1po8

### 5. FlashProve（Anthropic，11 月 2 日研究发布、11 月 3 日 TechCrunch 报道）——用密码学证明"这段回答真是某个模型生成的"
- **含义**：所谓 provable inference（可证明推理）：厂商先公开发布模型权重的密码学承诺（指纹，约 6.5MB、生成约 39 分钟）；之后对每一次请求，厂商可生成一份证明，验证方无需看到权重即可核对"这段输出确实出自被承诺的那个模型"。技术路线是基于哈希的 zkSNARK，针对 MoE 模型设计。
- **实测数字（研究原型，未独立验证，须带条件读）**：在 Meta 400B 参数 MoE 模型 Llama 4 Maverick（4-bit 量化）上，单张 H100 约 110 token/秒；每份 1024 token 请求的证明约 19MB，普通 CPU 验证约 17–21 秒；证明开销约为常规 vLLM 推理 GPU 时间的 70–95 倍。演示只支持最长 1024 token 上下文、贪心解码与特定的整数推理过程——离"给 Claude 对话框里每段回答都附证明"还很远。代码与技术规范已在 GitHub（anthropics/FlashProve）以 Apache 2.0 开源，但 Anthropic 明确称这是"中期研究进展、不是已完成的研究议程"，目前无在 Anthropic 或任何实验室部署的计划。
- **两个 caveat 必须同时记下**：① 证明只能绑定"输出 ↔ 承诺"，不能证明"承诺本身被诚实描述"——厂商若一开始就把便宜模型的指纹说成旗舰模型，证明也验不出谎言；② "证明了是谁做的"不等于"证明了内容可信"——模型身份真实，不代表回答正确。昨天日报的"水印证明 Claude 可能参与过"与今天的"证明证明某个模型确实算过"，是同一条"AI 产出可查证"线的两级：水印是事后痕迹，FlashProve 是事前承诺 + 事后验算。
- **与你的关联**：你多模型并行、又常把不同模型的回答交叉验证，FlashProve 回答的是你迟早会问的问题——"我付的旗舰模型价，拿到的真是旗舰模型的输出吗？"今天它还只是研究原型，不能当采购依据；但下次有厂商或中转服务宣称"可验证模型身份"时，先问它用的是水印式痕迹、还是承诺 + 证明式验算，以及证明开销由谁承担。

## 五、今日好用开源技能

### ① pixelfx（patch-gg）：244 个"用代码画出来"的像素风特效 + 教 Claude Code 自己画新的技能
- **一句话能力**：244 个像素风特效（火焰、爆炸、魔法、天气、UI、拾取、暴击等）每个都是一小段 JavaScript 代码、不是图片文件，可换色、镜像、导出精灵表给 Phaser / Godot / Unity 等引擎；附带的 Claude Code 技能会按"起草—渲染—看图—打磨至少三轮"的像素美术流程，帮你找现有效果、改效果或新画一个。
- **为什么今天推（10 月 30 日建仓的新库，11 月 1–4 日多家盘点在推）**：与你"AI 生图 + 视觉设计"的兴趣直接咬合，且形态很对"拒绝重复造轮子"——做小游戏、原型、活动页动效时，不用从零画逐帧动画，也不用去图库翻现成图，改几行代码参数就能出一套风格统一的特效。注意数字口径：README 计数为 244，仓库描述栏仍写 232（项目在快速增长中新旧计数未同步），今日按 README 的 244 写，描述栏的 232 不混用。
- **安装 / 获取来源**：https://github.com/patch-gg/pixelfx（多家 10 月 31 日–11 月 4 日盘点一致给出的仓库；MIT 许可，代码与特效可商用）。Claude Code 内：`/plugin marketplace add patch-gg/pixelfx` 再 `/plugin install pixelfx@pixelfx`；或把 `skills/pixelfx` 拷进 `~/.claude/skills/`；只用库不用技能时：`npm i github:patch-gg/pixelfx`，或直接拷 `src/core` + 需要的效果文件。
- **适用工具**：Claude Code（插件/技能主力）；库本身是纯 JavaScript，任何能跑 JS 的项目都能用，引擎侧靠导出的精灵表接入。
- **一句话上手**：先在图库里挑一个现有效果丢进你的页面/小游戏跑通"换色 + 导出精灵表"全链路，再让技能按"渲染—看图—打磨"流程给你新画一个——新效果一定要让 agent 真把图渲染出来看过，别只信代码写得像。
- **安全提醒（必读）**：① 技能的打磨流程需要 agent 能打开图片文件看渲染结果，装前确认你的 agent 有读图能力，否则"看图打磨"一环会空转；② 图库里的 Patch Pixel 字体不在 MIT 许可内（README 指向 NOTICE.md），商用发布前先核对该字体的许可，别连字体一起打包；③ 部分效果改编自 Sprite Fusion 作者 Hugo Duprez 的 MIT 代码、文件头有署名，复用时保留署名。
- **许可与时效**：MIT（代码与特效；字体除外）；2026-10-30 建仓，11 月 1 日前后约 2000 星量级（第三方盘点口径，今日未逐个实测全部 244 个效果，按"仓库与安装路径已核实、效果未逐个实测"推荐）。
