## 一、新词 / 出圈内容

### 1. 新词：RSI（Recursive Self-Improvement，递归自我改进）——Anthropic S-1/A 修正文件（11 月 2 日提交，11 月 3 日报道集中确认）
- **含义**：AI 好到能实质加速 AI 自身研发，于是能力提升不再靠人力线性推进、而是自我复合。Anthropic 的内部框架叫 Responsible Scaling Policy（RSP，负责任扩展政策），其中一个阈值叫"dramatically accelerated progress attributable to AI"（可归因于 AI 的急剧加速进展）——RSI 讨论的就是逼近这条线。
- **文件原话（按 TechCrunch 转引的 S-1/A 文本，须与"已发生"分开）**：① "internal estimates and expectations for upcoming models … indicate that we may imminently meet" 该阈值——主语是"对未来模型的内部估计"，不是现有模型；② "we have not designated any of our current models as exceeding this threshold"——现有模型无一被认定越线；③ 更值得记住的一句自我坦白："we have in the past not identified, and may in the future not identify, a significant acceleration in our rate of development until after it has occurred"——即它承认，过去有过事后才发现加速，未来也可能如此。也就是说，这份文件同时在说"快到了"和"我们的探测器未必能实时发现它到了"。
- **同一份修正文件里的财务数字（文件数字，非现金口径需分开）**：2026 年第三季度收入约 170 亿美元，前三季度约 332.4 亿美元（上半年 163 亿美元 + 第三季度约 170 亿美元，与 11 月 2 日日报的 S-1 口径衔接）；环比增速从第二季度的约 144% 放缓到第三季度的约 47%（第一季度约 132%，按 todaynewsbrief 整理的序列）；前三季度净亏损约 1040 亿美元、第三季度约 232.9 亿美元，但文件称大头来自可转债与衍生负债的公允价值变动等非现金会计项，不是烧掉的现金；九个月算力与基建费用增加约 144 亿美元（+329%），已承诺的采购与租赁总额约 8954 亿美元，几乎全是算力与基建。另有一项文件内披露：按标价算的 Claude 内部使用价值，自 1 月到 9 月增长超 250 倍，4 月起每月内部使用价值首次超过当月人力成本（不含股权激励）——这是"AI 帮自己干活"在账面上的另一面。
- **必须分开的三句话**：① "可能很快触及 RSI 阈值"是风险披露语言，不是"已实现自我改进的模型发布"，也没有新模型随文件上线；② "1.5–1.6 万亿美元估值"是市场报道中的讨论区间（aiweekly 称投资者在科技股抛售后把讨论价从约 2 万亿美元下调至该区间），文件里没有确认价格区间，11 月 2 日日报"2 万亿仍按传闻处理"的口径不变，只是传闻区间本身在变；③ S-1/A 是"提交修正文件"，不是"已上市"，首个交易日"11 月 16 日那周前后"仍是报道指向的窗口，未经公司确认。
- **为什么出圈**：这是第一家前沿实验室在 SEC 文件里把 RSI 阈值写成实质风险项——以前是会议与论坛话题，11 月 2 日起是法律文件里的措辞。Skeptics 的提醒也要记下：招股文件同时承担"强制披露"与"向投资者讲故事"两种功能，"快触及阈值"既可以读成风险警告，也可以读成能力信号，两种读法都不应只取其一。
- **与你的关联**：你不用追 RSI 哲学，但要盯它带来的两条实务线：① 11 月 12 日 Anthropic 新使用政策生效在即（见倒计时），"接硬件、须有人可监视并关停"等条款与这份文件的谨慎姿态是同一条线；② 下次再看到"AI 自己改进自己"的标题，先问一句：说的是"未来模型估计"、"现有模型认定"，还是"已上线功能"——今天这条三者皆非，只是"估计快到了"。

### 2. 新词：GDPx（SemiAnalysis，11 月 2 日发布）——"把 agent 当员工考"的基准
- **含义**：不是考"答得对不对"，而是把模型丢进一个模拟职场、给最长 8 小时、让它把一份工作从头干到尾：重建的私募股权交易（约 4000 份匿名文件里找关键材料）、芯片设计工具、实验室仪器、网络安全服务等。首版 206 个任务、11 个领域：芯片设计、硬件设计、网络安全、生物、金融、法律、量化交易、递归自我改进、材料科学、对齐、软件工程。领域按"经济回报潜力"选，不是按 GDP 占比——所以政府、房地产、保险这类大类不在里面。
- **成绩（SemiAnalysis 自报，任务未获外部独立审计）**：Claude Opus 5.5 以 12.0% 居首，Gemini 4 Carbon 10.9% 第二，GPT-6 Astra 9.6% 第三；最佳开放权重模型 GLM 5.3 为 2.7%。计分方式：每领域等权、首试通过率（pass@1）在三次尝试上平均，不是"三次里最好的一次"。模型跑在各自原生工具链里（Opus 用 Claude Code、Astra 用 Codex、Carbon 用 Antigravity、其余用 OpenCode 兜底）——所以这张榜测的是"模型 + 工具链"系统，不是裸模型。
- **两个最值得记的细节**：① 金融与法律在二元评分下"基本所有模型都是 0 分"，SemiAnalysis 因此只在该处另给部分分数——不是"模型不会金融"，而是"按'整单干完才算过'的严标准，全军覆没"；② 成本：Opus 每任务约 51.41 美元、Astra 约 53.99 美元，Carbon 按 officechai 的说法约为 Opus 的约三分之一、分数只低约 1 个百分点——"最强"与"最划算"不是同一名。另有 caveat：Opus 与 Astra 的安全分类器会在网络安全、生物、对齐领域拒答，SemiAnalysis 另有一张剔除这三个领域的榜，剔除后 Astra 以约 0.1 个百分点反超 Opus、Carbon 掉到第五——榜单名次对"算不算拒答域"敏感。
- **为什么出圈**：它把过去一个月"agent 越来越能干"的叙事反过来量了一次：Terminal-Bench、GPQA 这类"答题榜"上 60–90% 的分数，换成"在职场里干完一单"就只剩 12%。SemiAnalysis 每 3–6 个月刷新一次，下一次读数才是"这条线在爬还是在平"的证据；今天先别用 12% 论证"agent 没用"，也别用"答题 90%"论证"agent 能替代员工"——两个数字测的不是同一种事。
- **与你的关联**：你给 agent 排活时，GDPx 提供了一个现成的验收标准：不要只看"它答得像不像"，要看"交付物是否完整、规则是否被遵守、文件是否真的找到了"。下次让 Claude Code / Codex 跑长任务，先按 GDPx 的失败模式自查：中途丢文件、规则踩线、做到 90% 却交不出成品——这三类失败在 12% 的世界里才是常态。

### 3. Pando（OpenAI，11 月 2 日工程帖）——为成群的 Codex 重写 Git 后端
- **含义**：Git 兼容的后端，服务 OpenAI 自己的单体仓库（monorepo）。目标两个：多分支高并发写入（不同分支并行更新、分支内保持顺序）与高吞吐读取（fetch、clone）。实现语言 Rust，做法包括后台压缩（把小 packfile 逐步合并成更大的 cover，思路类似 LSM 树）。
- **厂商自报的数字（OpenAI 自家环境，未独立验证）**：中位 push 延迟降约 80%（约 5 倍）、合并可靠性提到 99.99%（此前低谷曾跌破 90%）、每天服务近 1 PB 的 Git 数据、单小时峰值发出超 57 TB 的 pack 数据。时间线注意：10 周从立项到生产、2026 年 4 月起接生产流量——11 月 2 日是"公开技术细节"，不是"今天上线"；且"1 名工程师设计核心 + 多组 Codex agent 实现 + 少数工程师部署"是 OpenAI 对自己项目的说法，不是"1 个人 + AI 就能复刻"的通用结论。
- **为什么出圈**：它是"agent 规模化"第一次把账算到基础设施头上：一个工程师用 Codex 并行推进多个改动、反复提交推送，仓库的读写压力不再是"人多"，而是"agent 多"。昨天日报的 Loop Engineering 在这里有了硬件版注脚：循环设计得再好，底下的版本控制、CI、存储跟不上，长程 agent 照样排队。
- **与你的关联**：你多工具并行、长会话跑仓库时，如果 push、fetch 开始变慢，先别只怪模型——先看是不是"并发分支太多、历史太大"的基础设施问题。Pando 本身不是开源产品、不能直接装，但它的思路可复用：分支并行时保持分支内顺序、读多写多分开治、压缩与缓存前置——这些在你自己的大仓库里同样适用。

### 4. Claude Message Threads（Anthropic，11 月 2 日公开测试）——长会话不再每次重传全文
- **含义**：Messages API 的服务端会话缓存。第一次请求照常发完整对话（含 system prompt 与 tools）并带 `thread` 参数建线程；之后每次只发新增消息 + 上一条响应的 ID，服务端在内存里把其余部分拼回来。Claude Code 上已对多数用户默认开启。
- **厂商自报的效果（未独立验证）**：50 万–100 万 token 的请求，中位首 token 延迟（TTFT）降约 35%；长会话里单次请求体从约 800 KB 缩到约 1.8 KB（AlphaSignal 转引的厂商内部测试，400 多倍是"上传量"不是"总耗时"）。**关键区分**：省的是延迟与上传量，不是账单——Claude 每轮仍要通读完整对话，token 用量、价格、限速都不变；prompt caching 仍需单独显式请求。
- **硬限制（官方文档口径，先记下再用）**：线程是 best-effort，5 分钟无请求即过期、过期后客户端须重发全文；内容只存加密内存、不落盘、最晚在最后一次使用后 1 小时内删除；没有列出/读取/删除线程的 API；不支持 Message Batches、token counting、按需压缩与多数上下文编辑；不适用于零数据留存（ZDR）与 HIPAA 组织，开启 Inference hooks 的组织会被拒绝。Anthropic 的原话精神是：**自己永远保留一份完整对话**，线程只是它前面的缓存，不是你的事实来源。
- **与你的关联**：你跑 Claude Code 长会话时"越到后面越卡"的体感，理论上从这周起会先缓一截——但别把它当成"上下文无限了"：5 分钟过期 + best-effort 意味着长思考、长工具调用后仍可能回落到重传全文；且合规场景（ZDR/HIPAA）下它根本不可用，选型时先看组织属性再看延迟数字。
