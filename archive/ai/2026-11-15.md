## 一、新词 / 出圈内容

### 1. 新词：Code Mode——Claude Code 让模型"写代码调工具"，而不是一句一调（v2.1.323，11 月 12 日 changelog；11 月 14–15 日 X 上讨论出圈）

- **含义**：Claude Code 的实验性 opt-in 功能。以前 Claude 每调一次 Bash/Read/Edit 都要回一轮对话、重读结果；开 Code Mode 后，Claude 直接写一段 JavaScript，一次把多个工具调用（并行、串联、过滤结果、只回传需要的部分）跑完，Claude Code 在会话内执行这段代码。启动方式：`CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude`，进会话时确认开启。官方文档原话："Code Mode is experimental and off by default. It may change or be removed in any release."
- **限制（官方文档口径）**：只在交互式终端会话里可用；`-p`、Agent SDK、VS Code 面板、桌面端、云端会话都不行；只走 Anthropic API（不用 Bedrock、Google Cloud、Foundry 或网关）；支持 Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.2；Remote Control、Claude in Chrome、computer use 开着时不能用；Code Mode 会话只能在开着 Code Mode 的终端里续接。组织可用托管设置统一关掉。
- **为什么出圈，以及一个必须纠正的数字**：周末 X 上到处传"省 37% token"。这个数字是真的，但不是这个功能的——它出自 Anthropic 2025 年 11 月 24 日介绍 API 侧 Programmatic Tool Calling 的文章（复杂研究任务平均用量从 43,588 降到 27,297 token，降 37%），测的是 API 里写 Python 的沙盒版，不是 Claude Code 的 Code Mode。Code Mode 官方文档里**没有任何省 token 的数字**。独立实测的方向一致、幅度不一，且都不是基准测试：wmedia.es 单次对照（Opus 5.5，40 个 JSON 文件找前三客户）输入 token 从 150,364 降到 94,659，但耗时从 15 秒变 37 秒；@kairofeed 在 Sonnet 5.5 上跑 8 次，称短任务约省 40%、30 文件重构省约 55%（486K→218K）。先别把任何一个数字当定论。
- **安全形态变了，要注意**：每一次工具调用仍过你的 deny/ask 规则与 PreToolUse hooks；但在 auto 模式下，分类器审的是整段代码、不是每一次调用，而且"看不到运行时算出来的值，比如从搜索结果里取出的路径"。Anthropic 的建议是：必须管住的调用，继续用规则或 hooks 兜底。调试也变了：出问题先读它写的脚本，再定位哪一步错。
- **与你的关联**：这不是 Anthropic 一家的方向——Rhys Sullivan 11 月 15 日在 X 上对比：Claude Code 用 node:vm（跑在 Bun 进程内），Codex 用 V8，OpenCode 用自定义解释器，Pi 用 quickjs。各家都在把"agent 一句一调"的聊天式调用，改成"一次写一段程序"的批处理。你的 Codex 团队里，多文件重复改、搜索后过滤、多个独立命令并行，正是官方建议 Code Mode 的场景；可以先在重复性任务上试，用 `/context` 自己量用量，别信网传的 37%。
- 出处：https://i10x.ai/news/claude-code-code-mode-javascript-tool-calls · https://dev.to/aicoding-guide/this-week-in-claude-code-codex-and-gemini-cli-week-of-november-15-2026-4pmm

### 2. Blackwell 指纹争议：六个中国开源模型的权重里有 Blackwell 痕迹，但"痕迹 ≠ 违规"（报告 11 月 12 日；11 月 15 日方法论遭质疑）

- **含义**：前 OpenAI 研究员 Will DePue 以 Unemployment Labs 名义发布报告，称在六个开源模型的权重文件里发现了 NVIDIA Blackwell 芯片的"指纹"：DeepSeek-V4-Flash 与 DeepSeek-V4-Pro（DeepSeek）、Kimi K3 与 Kimi K3.1 Pro（月之暗面）、MiniMax-M3、Ling-3.1-flash（蚂蚁）。美国禁止向中国出口 Blackwell 芯片（无许可），所以报告一出就被读成"出口管制被绕过"。报告自己的措辞比标题谨慎：指纹指向的是**生成初始权重的那块芯片**，"支持但不证明"训练用的是 Blackwell；它没有证明芯片在哪里、实验室怎么拿到的、是否违规。
- **11 月 15 日的反转细节**：DePue 又发了更详细的方法论说明，但 Hacker News 上的反应比 TechCrunch 报道时冷得多，质疑集中在四点：① 在新加坡、马来西亚等地合法租用 Blackwell 算力完全合规，指纹不等于违规；② 方法论代码未公开，无法复现；③ DePue 本人是出口禁令的公开支持者，立场需知悉；④ 一个被埋没的细节——DeepSeek 最新的 V4.1-Flash **没有** Blackwell 签名。截至今日，DePue 是否会公开代码仍未知，在此之前这件事停留在"合理但未证实"。
- **与你的关联**：这六个模型里有你日常用的 DeepSeek、Kimi、GLM 体系之外的 MiniMax 与 Ling——权重来源现在成了供应链问题的一部分：你选开源权重本地部署或接 API 时，"权重从哪来"和"跑在什么卡上"一样值得问一句。但现阶段别把它当定案写进任何选型结论：报告没有证明训练地点与违规，DeepSeek V4.1-Flash 反而没有该签名。

### 4. Memro：给 Claude Code / Cursor / Codex 做"跨会话共享记忆"，但现在只是个 6 星的早期项目（11 月 14 日 Show HN）

- **含义**：Go 写的记忆层，底座是 PostgreSQL 16 + pgvector，走 MCP 对外提供 remember / recall / get_recent_memories / delete_memory / export_memories 五个工具。一条 `npx memro-cli connect` 可自动配好 Claude Code、Cursor、Codex、VS Code、Claude Desktop、Antigravity、Windsurf。记忆分四类：语义（事实）、情景（事件与对话）、程序（指令与做法）、画像（agent 的约束）。
- **为什么只当"趋势"看，不当今日技能推荐**：仓库 10 月 18 日才创建，11 月 14 日核查时只有 6 star、1 fork；更重要的是许可证是 PolyForm Noncommercial 1.0.0——个人与非商业免费，商业使用须买 Memro Cloud 或企业许可，**不是 OSI 意义上的开源**。对比你库里已有的 claude-mem（11 月 2 日已推）：约 11.5 万 star、Apache-2.0、11 月 12 日刚发 v15.18.1，本地 SQLite + Chroma，同样覆盖 Claude Code / Codex / Cursor。Memro 的思路（Postgres 集中存、四类记忆、跨 agent 共享）值得记一笔，但成熟度与许可证都不够格进今天的技能推荐。
- **与你的关联**：Code Mode 解决"一次调太多工具"，记忆解决"下次开会话还要重讲一遍"。你的 Codex 团队换角色、换会话就要重讲架构与待办——这正是记忆层要补的洞。先看 claude-mem 这类已验证的，Memro 等它长大、换了许可证再说。

## 三、今日好用开源技能

今天两个都是"给 agent 补流程"的重型技能：一个治前端代码越写越旧（浏览器四家联手背书），一个把你的"大总管拆解、多角色并行"落成可复用的交付流程（腾讯开源）。Memro 因许可证与成熟度未达标，今日不推荐（见第 4 条）。

### 1. GoogleChrome/modern-web-guidance——浏览器四家联手出的前端技能：别让 agent 再用 2019 年的写法（v1.0，11 月 10 日发布；11 月 15 日 GitHub Trending 上榜）

- **一句话能力**：203 篇指南覆盖 250 个现代 Web 特性（CSS 与布局 140、JS 与 API 74、HTML 与 DOM 36），agent 干活时按需查指南再写代码；附 `legacy-scan`，先扫出现有代码里的过时写法再动手改。
- **为什么现在推**：Chrome、Edge、Firefox、MDN 四方共同维护，v1.0 于 11 月 10 日发布；已直接打开仓库核实：Apache-2.0，发布版仓库 GoogleChrome/modern-web-guidance 约 16,750 star（11 月 15 日核查时；另有一个 -src 源码仓约 4.5K star，装的时候认准发布版仓库，别装错）。评测数字有两个不一致的厂商口径：Chrome 博客转述称有指导时约 90% 检查通过、无指导约 50%；另一篇转述称预览期夜间评测为 88% 对 56%——两者都是厂商口径且口径不一致，以官方 Eval Dashboard 为准，别只记一个数。
- **安装 / 获取**：https://github.com/GoogleChrome/modern-web-guidance ；`npx modern-web-guidance@latest install`（交互式向导）；不装也能试：`npx modern-web-guidance@latest search "animate a dialog modal backdrop"`、`retrieve "animate-to-from-top-layer"`、`legacy-scan .`。另有 Claude Code / Codex / Cursor / Gemini 等插件清单。
- **适用工具**：Claude Code / Codex / Cursor / Gemini CLI / Antigravity / Copilot CLI 等（插件市场或 Skills CLI）。
- **一句话上手要点**：先在前端仓库跑 `npx modern-web-guidance@latest legacy-scan .` 看它挑出哪些过时写法，再决定装不装进 agent。
- **⚠️ 权限提醒**：`legacy-scan` 要读你的代码库；`npx` 会从 npm 拉包，装前看一眼 README 的 Telemetry & Privacy 一节。

### 2. Tencent/LoopForge——腾讯开源的自托管交付工作台：把"大总管拆解"写成 SOP，agent 按流程交活（11 月 9–13 日连发 5 个版本；11 月 14–15 日 GitHub Trending 上榜）

- **一句话能力**：自托管工作台：Main Bot 接需求后开 Docker 沙盒、 checkout 仓库、按角色分派给 Codex / Claude Code 等执行，最后开 PR；跑通的做法可存成 SOP（agent 节点 + 脚本节点 + 人工审批节点），下次同类需求照同一流程走；另有不用服务器的 LoopForge Local，直接把同一套分阶段流程装进你已有的 Claude Code / Codex / Cursor。
- **为什么现在推**：已直接打开仓库核实：11 月 15 日核查时约 1,189 star、249 fork，11 月 9–13 日连发 v0.3.4 至 v0.3.9-rc.1 共 5 个版本，仍在 0.3.x 早期阶段。执行器覆盖 CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Antigravity、Kimi Code、Pi、DeepSeek Harness、ZCode 共 10 种。这正是你 Codex 团队"大总管拆解、多角色并行"的腾讯版答案——区别是它把分工落成了可存、可审、可重跑的 SOP，而不是只存在对话里。
- **安装 / 获取**：https://github.com/Tencent/LoopForge ；完整平台：`git clone https://github.com/Tencent/LoopForge.git && cd LoopForge && ./start.sh`（需 Docker，MySQL 随栈起，默认监听 0.0.0.0:8090）；轻量 Local 版：`npx -y loopforge-cli@latest install claude`（写文件进 `.claude/`，不另起服务器）。
- **适用工具**：Claude Code / Codex / Cursor / CodeBuddy / Pi 等（Local 版）；完整平台另需 Docker + 服务器。
- **一句话上手要点**：先试 LoopForge Local（`npx -y loopforge-cli@latest plan claude` 看它怎么拆，再 `install claude`），别一上来就搭完整平台；注意角色提示词与 SOP 大多是中文写的。
- **⚠️ 权限提醒**：完整平台默认监听 0.0.0.0:8090 且注册默认开放（`.env` 里 `AGENTFLOW_ALLOW_SIGNUP=false` 可关），SOP 沙盒走宿主机 Docker socket（等于拿到宿主机 Docker 的控制权）——只给可信团队用，别直接暴露到公网；接 GitHub 与模型 key 前先看 README 的部署边界一节。许可证注意：README 徽标与正文称 MIT，但 GitHub 仓库元数据未识别许可证（NOASSERTION）——以仓库内 LICENSE 文件为准，商用前核对。
