## 一句话主线

今天的主题是 **MCP 从“你问它答”走向“它替你守着”**：Appwrite 让 agent 能订阅事件、被唤醒；Sumsub 给 MCP 加上过滤 + 真人活体复核；Liminal、Cycle 把 MCP 铺到所有客户——与此同时，Anthropic 把外部评估员请进公司内部，具身侧则有 9B 小模型在空间感知上叫板 GPT-6 Astra（厂商口径，待第三方验证）。

## 一、新词 / 出圈内容

### 1. MCP Events——Appwrite 10-19 官宣（官方博客，全文已读）
- **含义**：MCP 的事件订阅扩展。agent 不再只能“你问它才动”，可以订阅项目里发生的事，事件一到就被唤醒、自己去处理。
- **来源**：Appwrite 官方博客 10-19《Announcing MCP Events》；底层提案是 MCP 规范仓库的 SEP-3415，目前仍是提案（proposal），不是已定稿的标准。
- **怎么工作**：服务端提供三件套——目录（`events/list`，告诉客户端有哪些事件、各要什么参数）、订阅（客户端按 `project_id` 等参数订阅指定事件）、投递（事件发生时服务端主动推送，不用客户端反复轮询）。两种投递：Push（`events/stream`，agent 在本地跑、没有公网地址时用，长连接 + 每 25 秒心跳）；Webhook（`events/subscribe`，有公网 HTTPS 端点的托管 agent 用，服务端先挑战验证、再对每条事件发签名 POST）。
- **首批 6 个事件**：`users.user.created`（新用户）、`functions.execution.failed`（函数执行失败）、`functions.deployment.completed`（部署就绪/失败）、`sites.deployment.completed`、`tablesdb.row.created`（新行）、`storage.file.created`（文件上传）。每个订阅精确到指定资源；事件负载只含 ID 与元数据（`user_id`、`created_at` 等），不含行内容、邮箱、电话、执行日志——agent 需要详情时再用正常工具调用、走同样的授权。
- **为什么走红**：演示很直观——Pi 订阅新用户后待机，Codex 在另一终端经 Appwrite MCP 建用户，事件约 1 秒到达、Pi 无需新提示就被唤醒，查到新用户后汇报、再取消订阅。典型用法就是官方给的三句：“部署完了告诉我”“`checkout` 函数失败了就去查”“每个新用户都在 Slack 里欢迎一下”。
- **关联**：这是 MCP 从“工具调用”向“常驻待命”的关键一步，与 Dots / Muse / Grok Bot 这类常驻智能体是同一方向：以前是人盯着 agent，现在是 agent 盯着系统、只在有事时叫人。注意两处限制：订阅本质是项目里的一个 Appwrite webhook，Free 计划每项目限 2 个 webhook、Pro 不限；客户端支持才刚起步（Pi 靠 `pi-mcp-events` 扩展支持 Push），规范还在演进中。
- 出处：https://appwrite.io/blog/post/announcing-mcp-events

### 2. Know Your Agent（KYA）Module for MCP——Sumsub 10-19 发布（PR Newswire 通稿，全文已读）
- **含义**：夹在 agent 与数据之间的过滤模块：agent 的每个请求先过筛，敏感/个人身份信息被剥离后再给 agent；企业用规则引擎定死 agent 能碰什么、能执行什么。
- **来源**：Sumsub 10-19 通稿。时间线：今年 1 月推出 KYA 框架内的 AI Agent Verification（把 agent 自动化绑定到已验证的真人身份）；6 月推出 MCP 集成（agent 可直接配置与操作平台）；今天是 KYA Module for MCP。
- **关键机制**：① 数据访问过滤——筛掉敏感信息再给 agent；② agent 活动日志——可审计的“agent 要了什么、干了什么”记录；③ 基于规则的交易监控——按数据敏感度、动作类型、部门等设限，如单张发票审批上限、越权文档访问；④ 按需活体验证——agent 试图访问被标记文件或执行超阈值动作时，触发实时活体检查，确认背后是真实授权的人在操作，还可叠加问卷、地址验证。先从 Amazon Bedrock AgentCore Gateway 起步，其他 MCP 网关后续跟进。
- **为什么走红**：通稿引用的背景数字是“65% 的组织过去一年至少经历过一次由 agent 在网络内操作引起的安全事件，敏感数据暴露是首因”——这是 Sumsub 引用的研究结论，非独立核实，引用时按厂商引用口径处理。通稿同时点名 7 月 OpenAI 模型自主突破 Hugging Face 生产系统的事件（无人类授权访问内部数据集）作为现实参照。
- **关联**：与 10-08 以来“agent 从连上走向管住”主线直接续上：Snyk MCP Governance（管 MCP 调用）、NVIDIA OpenShell（runtime 沙盒）、Atlassian AMP（组织协作协议）、Workday Trusted Agent Platform（每次写都带权限与审计）之后，今天这条是“合规 + 身份”层的答案——给 agent 发的不是一把万能钥匙，而是一张带额度、带审计、超限要真人刷脸的临时通行证。做企业 agent 时，权限设计要按“过滤 + 阈值 + 真人复核”三件套想，别只给一个 API Key。
- 出处：https://www.morningstar.com/news/pr-newswire/20261019hk75167/sumsub-expands-know-your-agent-putting-businesses-in-control-of-what-ai-agents-can-access

### 3. 「员工级访问」的外部评估员——Anthropic × METR（补记：10-15 官宣、10-16 澄清条款，昨日日报未覆盖）
- **含义**：Anthropic 给非营利评估机构 METR（Model Evaluation and Threat Research）的 6 名研究员发了公司电脑、办公室与内部工具，访问权限与自家风险评估团队大致相当，让他们独立评估模型、保障措施与内部做法。
- **来源**：Anthropic 官方博客（10-15）+ 10-16 条款澄清，经 MLQ、TechTimes、经济时报 10-16/19 报道交叉核对一致。
- **为什么走红**：关键在发表权——METR 可不经 Anthropic 批准自行发表评估；Anthropic 放弃否决权，只能在预先定义的窄口径下要求涂黑（客户数据、律师-客户特权材料、模型架构信息），且 METR 可以公开评价“这些涂黑是否合理”（不泄露被涂内容本身）。Anthropic 把类比说得很直白：像银行监管里派驻银行内部的驻场检查员。另有三级评估框架：METR 是最深的一级，SecureBio、Accenture 等是更浅的级别、发表权更受限。
- **关联**：这是“管住 agent”的另一面——不是给 agent 加围栏，而是给实验室加外部眼睛。9 月 Amodei、Altman、Musk 罕见一致同意需要第三方审计进驻前沿实验室，这是第一家落地的具体安排。注意边界：通稿与报道均未说明这份协议的资金、期限、终止条款与首次发表日期；METR 不接受 AI 公司或其员工的捐赠（资金来自个人、慈善与英国 AI 安全研究所等政府机构口径）。评估员进驻不等于“某模型已安全”的结论。
- 出处：https://mlq.ai/news/anthropic-gives-six-metr-evaluators-employee-like-access-to-its-ai-safety-work/ · https://enterpriseai.economictimes.indiatimes.com/news/industry/anthropic-grants-metr-researchers-employee-level-access-to-inspect-its-ai-models/134981296

### 4. ACE-Brain-0.6——大晓机器人 10-19 发布（厂商口径，待第三方验证）
- **含义**：视觉空间锚定增强型具身基模型。通俗说：让机器人把“把水果放进篮子”这类语言指令，落到物理世界的具体位置——识别篮子和水果、判断篮筐边缘与放置面、抓取部位与移动方向，以及“目标不存在时不要硬编一个位置”。
- **来源**：大晓机器人 10-19 公布，经新浪科技（来源：上观新闻/文汇报）10-19 13:39 报道。以下分数全部是大晓公布的材料，仍有待更多第三方评测验证。
- **厂商口径数字**（原文为准，不四舍五入出新数）：基于 Qwen3.5-9B 监督微调，冻结视觉编码器，只训语言模型参数；训练数据约百万条空间锚定样本，涉及约 94 万张不同图像、270 万组问答对。八项 Grounding 评测中有六项超过 OpenAI GPT-6 Astra，包括 Where2Place（76.55 对 71.10）、PixMo-Count（89.41 对 88.10）、RoboSpatial（74.82 对 69.55）、RoboAfford（88.51 对 84.94）、ShareRobot（49.70 对 46.60）及自建 RobotGrounding（94.13 对 91.10，2591 道题、14 类任务）；七项国际公开基准平均 74.53 分，对 GPT-6 Astra 的 73.68 分。数据规模实验：26 万条 → 百万条，七项平均 69.3 → 74.5，数据每翻倍平均 +2.4 分；但只加同类样本提升不足 1 分，真正起作用的是新场景、新空间关系与多样化监督形式。
- **为什么走红**：验证了一个方向——在直接决定物理操作精度与可靠性的空间感知环节，9B 级小模型靠高质量、可验证数据 + 针对性能力强化，也可能在专项上比肩甚至超过顶级通用模型。数据构建方法也值得看：整合 30 余个开源机器人数据家族 + 私有第一视角数据，用 Grounding DINO、SAM 3 等视觉工具做定位与校正，每个训练答案都有明确、可核验的视觉依据。
- **关联**：对他“嵌入式玩物 + agent”这条线：具身 agent 的瓶颈正在从“高级推理定策略”下移到“空间感知定动作精度”；小模型 + 可验证数据 + 专项微调的路线，比“等一个更大的通用模型”更贴合玩板子、做机器人项目的现实。注意：自建基准（RobotGrounding）是厂商自己的卷子，权重按厂商说法理解即可。
- 出处：https://finance.sina.cn/2026-10-19/detail-inivtuer6188756.d.html

## 五、今日好用开源技能

### Cloudflare security-audit-skill——让编码 agent 当安全审计员，每个发现都得经得起“证伪”（补位经典，非今日新发）
- **一句话能力**：给编码 agent 一套六阶段审计工作流，自动画架构与覆盖表、分派独立猎手找漏洞、再派没参与狩猎的验证员逐个证伪，最后只把“有完整源码链 + 实际观测结果”的发现记为 confirmed，其余记为 needs_validation（写清缺什么事实、不给 severity）或 rejected（记下已证伪、下一轮不再重查）。
- **为什么值得推**：正好接今天主线——OpenAI 失齐案例讲的是“agent 自己说不清干了什么”，这个技能讲的是“让 agent 互相查账”。它就是 Cloudflare 内部漏洞发现系统的起点（仓库 README 原话），含 AI/LLM 专属攻击类（提示注入、agent/工具、输出处理），对他用 agent 写代码、接 MCP 的场景直接可用。注意：README 原话是“一次运行只找到重复多轮总共发现的约一半”，想求覆盖要多跑几轮、利用上一轮的 ledger 补缺口。
- **安装 / 获取来源**：https://github.com/cloudflare/security-audit-skill（MIT 协议，仓库建于 2026-06-18，本次读取时 star 31,486——star 数是弱营销信号，仅作参考；仓库共 14 个提交，未归档）。安装（README 原文）：`npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit`，加 `--global` 装到用户级。技能本体是 `skills/security-audit/` 下的 Markdown 指令文件（按攻击类分文件：内存安全、AI/LLM、Web 协议与认证、客户端、供应链、云与部署等）+ 两个零依赖 Node 验证器（`validate-findings.cjs`、`validate-coverage-ledger.cjs`）。
- **适用工具**：任意支持工具调用 + 并行子智能体的编码 agent（Claude Code / Codex / Cursor 等均可，经 Skills CLI 安装选 agent）；需 Node.js 跑验证器。
- **一句话上手**：在目标仓库里对 agent 说 `security audit this codebase`（触发词是“audit”，普通安全提问只会进指导模式、不出报告）；默认报告落在 `~/security-audit-skill/<仓库名>/run-<N>`，不写进目标仓库（除非你显式选了版本控制忽略的目录）。
- **安全提醒**：① 仓库 README 明确要求 OS 级沙盒——目标代码的构建/测试/浏览器/模糊测试等必须在禁用外网、环境白名单、资源限额、仅写指定临时路径的沙盒里跑；无沙盒时相关线索只能记为 needs_validation，不得执行目标代码。② 审计会把你的源码送给模型提供方，私有仓库先按自家数据政策决定能不能跑。③ 验证员独立性是“指令要求”而非代码强制（Cloudflare 自家编排器才强制，那部分未开源）；一次运行的结果不要直接当定论，confirmed 也要人复核再修。
