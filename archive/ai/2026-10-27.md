### 1. GPT-6.1 Terra：OpenAI 的"便宜电脑操作档"——看屏、点按、填表，价格是 Sol 的一半
- **含义**：GPT-6.1 Terra 是 GPT-6 家族里的中端档，定位在 Luna（最便宜）之上、Sol / Astra（更强更贵）之下。上一代叫 GPT-5.6 Terra，这次是换代不是小修。"电脑操作（computer use）"指模型把屏幕当图像看，认出按钮和表单字段，再像人一样点按、输入、在应用之间切换——不是只聊天，而是直接动手办事。
- **发布时间口径**：OpenAI 官网发布页（美东 10-26）+ AWS Bedrock 同日 GA；北京时间 10-27 上午中文媒体跟进报道。写"10-27 发布"或"10-26 发布"都对得上时区，别写成"10-27 才首次出现"。
- **价格（官宣）**：标准 API 价每百万 token 输入 $1、缓存输入 $0.05、输出 $5——官方称比 GPT-5.6 Terra 和 GPT-6.1 Sol 均低 50%。API 调用名 `gpt-6.1-terra`。在 ChatGPT Work 和 Codex 里，同一份额度用 Terra 能跑的任务比用 Sol / Astra 多得多（厂商口径）。
- **能力数字（全部是 OpenAI 厂商口径，尚未独立验证）**：
  - Agents' Last Exam（把建筑图纸转 3D 模型、逐镜头审动画片做修复日志这类专业任务）：中等推理强度下比 GPT-5.6 Terra 高 15 个百分点、成本约三分之一，成绩与旗舰 GPT-6 Astra 相当、每 token 价格仅为后者约十分之一；速度比 Astra 和 Sol 快 3 倍以上。
  - 事实性：内部"易诱发错误提示"测试里，低推理强度错误率从 GPT-5.6 Terra 的 53.6% 降到 16.7%，最高强度降到 4.3%，接近 Astra / Sol。
  - 编程：Terminal-Bench 4.0 最高强度解决 50.3%，是 GPT-5.6 Terra 公开成绩 21.5% 的两倍多；Terminal-Bench-Science 0.1 最高强度超过 Sol，距 Claude Opus 5.5 不足 5 分。
  - 视觉推理 MMMU-Pro 各档均优于上一代；桌面操作 OSWorld 2.1 中等强度即超过上一代的最佳成绩。
  - 安全：按 OpenAI Preparedness Framework 网络安全评估达到 Critical 级，沿用 Astra 的防护；官方称更易守住任务范围、对提示词注入抵抗力增强。**注意**：Critical 是"能力等级"（模型能做到什么），不是"已通过安全认证"的意思，别写反。
- **为什么走红**：过去出圈的都是"最强模型"，这次出圈的是"最便宜的够用模型"——电脑操作类 agent 此前贵到只能小规模跑，Terra 把单任务成本压下来后，批量读发票、往会计软件录入、填表、审图纸这类活才具备大规模上线的账面条件。同时它一天内铺到四个入口：OpenAI API、ChatGPT Work / Codex（Plus、Pro、Enterprise、Edu）、GitHub Copilot（Pro / Pro+ / Max / Business / Enterprise，逐步放量）、AWS Bedrock GA——这不是单一产品更新，是 OpenAI 一次把"量大管饱档"铺进所有工作流。
- **与你的关联与选型建议**：
  - 你用 Codex / ChatGPT Work 的话，Terra 是"先试它，跑不动再升 Sol / Astra"的默认档——OpenAI 自己也明说：最难的编程和推理仍选 Sol / Astra。
  - 做 agent 选型别只看榜单分：Terra 的卖点是"单任务成本"，评估时按你自己的任务跑一遍、算"每个办成的任务花多少钱"，而不是比单价。
  - 对照全景表变化：全景表（10-16 快照）里 OpenAI 一栏只有 GPT-6.1 Sol 作默认模型、Terra 档还是 GPT-5.6 时代的旧位——**Terra 是 11 月 1 日刷新时必须新增的一行**：GPT-6.1 Terra、$1/$5、Work / Codex / API / Copilot / Bedrock 均已上线。

### 2. IBM 给企业 agent 发"身份证"：Vault 管凭证、Orchestrate 管发现与停机
- **含义**：IBM 在 TechXchange 2026（10-27，亚特兰大）宣布的不是一个新模型，而是一套"agent 身份与管控"能力：每个 agent 有可验证的身份、只拿最小权限、所有动作可追溯到负责人。背景数字（IBM 引用 Gartner，厂商口径）：到 2028 年平均每家 Fortune 500 企业将用超过 15 万个 agent，但只有 13% 的组织认为自己已有合适的 agent 治理。
- **两件具体东西**：
  - **HashiCorp Vault 扩展到 agent**：给 agent 发短期凭证、越权操作时可实时吊销；Vault 2.2 增加 agent 专属账号、自动续期、后量子加密，另有 Secure Hub 公开预览、集中看各 Vault 部署。
  - **watsonx Orchestrate 统一发现、围栏与评估**：技术预览里可跨 Amazon Bedrock、Microsoft Foundry、Google Gemini 发现外部 agent，沙箱围栏 + 一键停机（kill switch）可叫停失控进程，并跟踪模型成本与 token 用量。
- **为什么走红**：这是 10 月"agent 从连上走向管住"主题在企业侧的落地版——10-06 的 Snyk MCP Governance 管的是 MCP 连接、NVIDIA OpenShell 管的是运行时沙箱，IBM 管的是"谁在办事"这一层：身份、凭证、归属。三层拼起来，企业才敢把 agent 放进真实业务系统。注意它不绑定自家模型，恰恰是跨平台管控，这才是它被转述的原因。
- **与你的关联**：你个人用 Codex / Claude Code 时用不上 Vault，但这个思路可以直接借用：给自己的 agent 立三条规矩——凭证只给最小权限且定期换、长任务分段 checkpoint、会改动外部系统的操作先只读演练。Pomerado（10-26 日报）那套"先只读集成练手"就是同一逻辑的个人版。
- 出处：https://www.morningstar.com/news/pr-newswire/20261027ny81742/ibm-introduces-identity-and-control-for-ai-agents-securing-frontier-intelligence-for-the-enterprise（PR Newswire 10-27 通稿转述，Gartner 数字为 IBM 引用口径）

### 3. 华大九天 .aix：国产 EDA 也进入"Agent 协同设计"——"设计靠 AI，验证靠签核"
- **含义**：国产 EDA 龙头华大九天在 HUG 2026 生态伙伴及用户大会上发布 .aix 系列 AI 智能体平台：每款 EDA 工具配一个陪伴式 Copilot 智能体，把"人操作工具"变成"agent 协同设计"，目标是 7×24 小时不间断跑设计流程。底座是国产开源大模型 + 自家工具引擎与数据积累，并配安全沙箱、灾难处理和基于签核计算引擎的分析评测——官方口号是"Design by AI，验证靠签核"，即 AI 可以大胆试，是否过关由签核说了算。
- **四个子产品（均为厂商/报道口径，未独立验证）**：Custom.aix（模拟电路：周/月级参数调试与版图压缩到 1 天内，设计迭代减少 60%，PPA 提升 5 倍以上）；FPD.aix（面板像素设计：专家一周的工作量压缩到 1 天内，效率提升 7 倍以上，画质指标提升 5 倍）；Digital.aix（开源 CPU 案例：生成 200 余个标准单元、118 个带来正收益，最高频率从 1.81GHz 提升到 1.83GHz，超过 1% 的预设目标）；Manufacture.aix（长程 Pcell 任务从数天压缩到半小时内，Dummy Fill 空间利用率从人工 78% 提升到 93%）。
- **为什么走红**：EDA 今年已是 agent 主战场——Synopsys（3 月 AgentEngineer、9 月 AgentEngineer + Autopilot）、Cadence（2 月 ChipStack AI Super Agent、9 月新增 RTL 生成与优化智能体）、Siemens EDA（Fuse EDA AI Agent 等）都已入场；国内合见工软、芯华章、芯和半导体也在推，合见 UDA2.0 已商用。华大九天是国产 EDA 里体量最大的一个入场，补上了"国产工具链 + agent"这一块拼图。
- **与你的关联**：你玩 ESP-IDF / 开发板时接触的是"板子级"智能体（AMD Ross、Muse Gadgets），.aix 是再往上游一层——"芯片设计级"智能体。两件事的共同趋势值得记一句：智能体正在从"帮你写代码"向"帮你跑专业工具链"渗透，而"AI 做、签核验"这种"生成与验证分离"的结构，正是让 agent 进高风险流程时最可复用的安全模式。

### ① kicad-happy —— 给 Claude Code / Codex 装一套"懂电路板的评审员"（补位经典，非今日新发）
- **一句话能力**：AI 编码助手读 KiCad 原理图与 PCB 的技能包：审原理图、审版图布局、EMC 预合规检查、SPICE 仿真、下载元器件 datasheet、找货源、为打板做准备——把"画完板子凭感觉送去打样"变成"先过一遍机器评审再送"。
- **安装 / 获取来源**：https://github.com/aklofas/kicad-happy（作者 aklofas；检索时约 1515 stars，Python 为主）。安装（来源站转述 README）：`git clone https://github.com/aklofas/kicad-happy` 后按 README 指引放进 Claude Code 的 skills 目录；另有 GitHub Action 可在 PR 触及 KiCad 文件时自动出评审（电源树、SPICE 结果、EMC 风险、热分析等）。
- **适用工具**：Claude Code、Codex CLI（来源站口径；另有 mcp-server-kicad 等同类项目走 MCP 路线，别混装）。
- **一句话上手**：先拿一块已打过样的旧板子跑一遍评审，对照你已知的板子问题看它报得准不准——准了再把它放进新板子的送板前检查清单。
- **安全提醒（必读）**：① 它会读你的全部设计文件、联网下载 datasheet 与查货源——含未公开硬件设计的项目先在副本上试，别直接对唯一原文件跑改动类操作；② 评审结论是"预检查"不是签核：EMC、载流、散热这类结论落到实物前，仍以 KiCad 自身 ERC/DRC 与实测为准，打板前的人工复核不能省；③ 找货源、替选器件涉及采购决策，型号与封装以 datasheet 原文为准，别让模型替你定料。
- **为什么今天推**：你玩 ESP-IDF / 开发板，迟早会走到"自己画板子"这一步——这正是把 agent 能力从"写固件代码"延伸到"审硬件设计"的现成轮子，且不在此前技能库中；标注为补位经典，不谎称今日新发。
