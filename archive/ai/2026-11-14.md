## 一、新词 / 出圈内容

### 1. ChatGPT Wallet：Dots 能替你买东西了，卡号 agent 看不到（11 月 13 日，OpenAI 官宣）

- **含义**：OpenAI 推出 ChatGPT Wallet，常驻智能体 Dots 第一次能替用户完成购买。卡绑一次；每次下单前用户先核对商品、总额和卡，再用 Face ID / 指纹等安全检查确认；支付网络给每笔交易发一个一次性 token，agent 和商家都看不到真实卡号；原有积分、返现与争议保护不变。OpenAI 称上线初期不抽成（CNBC 口径），并同步发布了给商家的《Commerce Partner Playbook》，还与 Forter、Riskified、Sardine、Signifyd 等反欺诈公司及 Adyen、Checkout.com、Stripe 合作。
- **范围**：首批只面向美国 18 岁以上 ChatGPT Pro 用户（须美国发行的 Amex / Chase / Mastercard / Visa 信用卡 + 美国账单地址），逐步放量；借记卡与虚拟卡首批不支持；只在与 dot 的对话里可用，不在 Chat、Work 或独立 Codex 线程里。完全托管式代买（预设额度、品类、时段内自动买）已上路线图，未给日期。
- **为什么出圈**：这是"常驻智能体"从"帮你挑"到"替你付"的临门一脚——Dots 9 月 29 日发布时只会办事不会花钱，现在补上了最后一环。而且它正好撞上昨天的反向新闻：11 月 12 日 United 宣布拦下未经授权的 agent 代订机票。两边同时在划"谁能替你花钱"的线：OpenAI 修支付链（token + 每笔人工确认），商家修准入（没授权不许买）。Amazon 同样在拦 agent 下单。
- **与你的关联**：你搭 Codex 团队最关心"agent 替你办事"的边界——Wallet 的设计值得抄：真卡号不进 agent 上下文、每笔交易单独确认、额度托管留待以后。对你现在在国内用不上（美国 Pro 专属、无出海时间表），但它是"agent 消费"这条线的标杆实现：以后你的团队要接任何花钱的动作，都按这个模式设审批。
- 出处：https://openai.com/index/introducing-chatgpt-wallet/ · https://9to5mac.com/2026/11/13/openai-launches-chatgpt-wallet-enabling-dot-agents-to-make-purchases/

### 2. 新词：Poppy（Personal Agent Protocol）1.0——个人 agent 进店的"身份证 + 店规"（11 月 13 日，Sierra 官宣）

- **含义**：Sierra 与 Meta 联合制定的开放协议 Poppy 发布 1.0：公司在域名下放一个 `poppy.json`，告诉来访的个人 agent"我是谁、你能干什么、怎么证明你是替谁来的"。Shopify 已为全平台所有商店自动发布 Poppy 文件（覆盖 175+ 国家的商家，无需商家动手）；Meta 的 Muse 探访任何网站时都会先找 Poppy；新增 60 家设计伙伴，总数超 100 家（Cisco、Delta、Intuit、Salesforce、Twilio、Zoom 等）。协议大量复用现有标准：MCP、OpenAPI、UCP（Shopify 的通用商务协议）、OAuth；Shopify 还联名写了连接 Poppy 与 UCP 的商务扩展，agent 可以访客或登录身份购物，购物车与结账走 UCP。
- **注意点**：Sierra 叫它 v1.0，但规范本身仍标为 draft 1.0，允许不向后兼容的修改；支付、推送通知、附件仍是开放议题。设计伙伴名单不等于已上线——真正开箱即用的目前是 Shopify 全量商店与 Muse。
- **为什么值得看**：这是"agent 从连上走向管住"主题在商业协议层的一站：10 月 Snyk MCP Governance（管工具调用）、NVIDIA OpenShell（管 runtime 隔离）、今天 Poppy（管 agent 以什么身份进别人家的门）。而且它和 United 的拦截是同一枚硬币的两面：United 拦的是"没打招呼就来的 agent"，Poppy 就是"打招呼"的标准格式。
- **与你的关联**：你关心 MCP 与 agent 互操作——Poppy 是 MCP 之上的又一层协议：MCP 管"agent 怎么调工具"，Poppy 管"agent 以谁的名义进谁的店"。你以后让 Codex 团队替你对接外部服务（订票、下单、查订单）时，对方支不支持 Poppy 这类协议，直接决定 agent 是走正门还是爬窗户。
- 出处：https://sierra.ai/blog/releasing-poppy · https://www.descope.com/learn/post/personal-agent-protocol

### 3. Cursor 安全事件完整报告：Fireworks 泄露的密钥，一路走到假插件（11 月 13 日，Cursor 官方博客）

- **含义**：Cursor 公布了 10 月 29 日首次披露的安全事件的完整调查。起点在 Fireworks（Cursor 的推理与训练供应商）：攻击者拿到 Cursor 发给 Fireworks 的一把访问密钥（Fireworks 方面泄露），复制了一个只读存储桶里的编程 agent  traces——主要是 2025 年、未开 Privacy Mode 的会话。极少数 traces 里有未脱敏的凭证（不到 0.01% 的客户 API 凭证泄露），攻击者凭此进入 Cursor 的部分 SaaS 工具，拿到归档的非生产代码库、客服数据与邮件对话、用量指标、联系方式、部分 agent 对话摘要，以及用户发给客服的凭证。
- **最严重的一步**：10 月 29 日，攻击者用偷来的内部凭证，把 Anthropic Claude Code 扩展的恶意仿冒版（2.1.312 / 2.1.313）直接放进 Cursor VS Code 扩展市场的缓存。约 11 小时、至多 5000 名用户可能拿到恶意构建。Anthropic 没有发布这个版本，也不是 Anthropic 产品的漏洞；上游 Open VSX 从未染毒。最后一次攻击者活动在 11 月 1 日，已被拦截。
- **已确认未受影响**：开 Privacy Mode 的用户提示词与代码；不到 0.05% 用户的 traces（已逐一通知，未收到通知即未受影响）；实时推理流量、生产系统、Cursor 客户端与官方更新、客户代码仓库、Cloud Agents 与 Grok Bot 等其他产品。Cursor 已把全部推理迁出 Fireworks、轮换了全部内部凭证、重建了扩展市场、重新部署了生产 infra。
- **与你的关联**：这是本周第二起"供应商的供应商出事"（第一起是 Notion：Fireworks 同一家供应商出问题，Notion AI 聊天记录泄露，不到 1% 的工作区受影响——Fireworks 合同承诺零留存，照样出事）。教训和 11 月 12 日的 Lazarus 一脉相承：agent 生态的安全短板不在你自己的提示词，在你看不见的供应链——发给供应商的密钥、训练用的 traces、扩展市场的缓存。实操两点：如果你 10 月 29 日在 Cursor 市场装/更新过 Claude Code 扩展 2.1.312 或 2.1.313，按 Cursor 安全公告的步骤检查，只卸载扩展不够；另外检查你自己的工具链里有没有"发给第三方、以为对方会脱敏"的数据。
- 出处：https://cursor.com/blog/security-incident-update

### 4. Antigravity Dynamic Workflows：agent 写 Python 脚本指挥一群 subagent（11 月 13 日，Google 官宣）

- **含义**：Antigravity 新命令 `/run-workflow`：你一句话提需求，agent 先写一段简短的 Python 脚本，把活拆成有名字的阶段——`parallel()` 让每个 subagent 并行干一个文件/包，`pipeline()` 让它们按顺序接力，每个结果按 JSON Schema 结构化校验。你先审脚本、通过了才跑；脚本可保存、反复跑。Google 的说法是"用确定性的控制流，替代一条越聊越飘的长对话"。适用 Google AI Pro 与 Ultra，在 Antigravity App 与 CLI 里，不另收费、走套餐内模型额度；脚本跑在独立进程里，用 Antigravity 自带的 Python 运行时，本机不用装 Python。
- **配套**：11 月 12 日还推出了 Orchestrator（Ultra 专属）：一个会话内动态换模型——Carbon 先做只读调查、定计划，Hydrogen 接手改代码跑测试；厂商口径称 Terminal-Bench 4.1 上接近 Carbon 的任务成功率，平均省 24% 额度、快 19%。这是 11 月 10 日 Carbon 与 `/swarm`（多 agent 并行大工程）之后的第三块拼图：swarm 管"一群 agent 分头干"，Orchestrator 管"一个会话里换模型"，Dynamic Workflows 管"把分工写成能复用的脚本"。
- **与你的关联**：这正是你 Codex 团队"大总管拆解、多角色并行"的 Google 版答案——而且它点出了你团队下一步最缺的东西：分工不该只存在对话里，要落成一份可审、可存、可重跑的"执行脚本"。你的 Codex 团队目前靠大总管在对话里协调；Antigravity 的做法是把协调本身写成代码。值得在你的团队流程里抄一笔：复杂任务先让大总管出一份分工脚本（谁并行、谁接力、谁验收），再开工。
- 出处：https://antigravity.google/docs/dynamic-workflows · https://alphasignal.ai/news/google-antigravity-ships-dynamic-workflows-to-run-parallel-ai-coding-agents

### 5. Microsoft 365 全球宕机近 24 小时：Copilot 跟着邮件一起倒下（11 月 12–14 日）

- **含义**：11 月 12 日约 16:00 GMT 起，Microsoft 365 全球中断：Outlook、Teams、SharePoint、Copilot、Defender 陆续无法访问，Downdetector 一小时内收到 74 个国家/地区的报告，Outlook 投诉峰值约 14 万条（约为平时的 2000 多倍）。持续 22 小时以上，至 11 月 14 日周六微软宣布全面恢复，并承诺出完整事后报告。微软口径：技术问题，与网络攻击或 AI/agent 无关；根源是早前一次网络容量升级引入的问题，在最近一次网络变更后爆发。
- **为什么值得看**：Copilot 是"长在 Office 里"的助手，邮件一倒它也跟着倒——agent 接入邮件、日历、文档的那一刻，也就继承了这些系统的故障模式。英国政府与 NHS 员工受影响（999 与 NHS 111 未受影响）。对"常驻智能体"赛道是个提醒：Dots、Muse、Grok Bot 再能干，底下的邮箱、会议、日历服务一停，它们也只能干等。
- **与你的关联**：你的 Codex 团队跑在本机、资料不出本机，这次宕机恰好说明这条路线的价值：云端助手全家桶一停就是一整天，而本地团队只要本机与模型 API 还在就能继续干活。反过来提醒：你的团队里凡是依赖单一云服务（如某个云端模型 API、钉钉同步）的环节，都该留一条备用路线。
- 出处：https://www.bbc.com/news/articles/ （BBC 报道，转述）· https://www.capetownetc.com/news/microsoft-apologises-global-outage-not-related-cyber-ai/

### 6. LangChain 30 亿美元估值：agent 基建单独成了一个赛道（11 月 13 日，TechCrunch / 公司官宣）

- **含义**：LangChain 宣布完成 3 亿美元 C 轮，估值 30 亿美元，由 CapitalG（Alphabet 成长基金、老股东）领投，GIC、DFJ Growth、IVP、Sapphire 等参投；累计融资 4.6 亿美元。上一轮约一年前：1.25 亿美元、B 轮、估值 12.5 亿美元——一年估值翻 2.4 倍。主打产品 LangSmith：不绑定模型的 agent 创建与管理平台，公司口径称服务 7000+ 组织（含 Nvidia、Toyota、Salesforce 等，未独立验证）；未公布收入与盈利数据。
- **为什么出圈**：LangChain 2022 年起家时只是个开源 LLM 工具库，现在资本市场按"agent 操作系统"给它定价——估值翻倍的不是模型，是"管住 agent"的那层基建（运行、评测、可观测、治理）。和今天的 Poppy、Wallet 连起来看，agent 生态的钱正在从"模型本身"流向"让 agent 可靠花钱、可管、可复核"的周边层。
- **与你的关联**：你搭 Codex 团队、攒开源技能库，本质上也是在搭自己的"agent 基建"。LangChain 的估值说明这条路有商业价值，但也提醒：LangSmith 这类平台解决的是"企业级 agent 治理"，个人/小团队用开源技能 + 本地流程搭轻量版，性价比更高，不必照搬企业级方案。
- 出处：https://techcrunch.com/2026/11/13/ai-agent-startup-langchain-hits-3b-valuation/

## 三、今日好用开源技能

今天 GitHub 日榜的主角是"agent 干完活，谁来审"：阿里开源的评审 CLI 冲上日榜第一，另有一个给 agent 计划与 diff 开浏览器批注面的本地工具——正好接上今天 Daybreak、Poppy、Cursor 事件的主题：审，要落在流程里。

### 1. alibaba/open-code-review——阿里内部两年的 AI 代码评审 CLI：确定性流水线挑文件，LLM 只负责看

- **一句话能力**：一个 `ocr` 命令行：读 git diff，用确定性工程逻辑选文件、打包上下文，再让 LLM agent 写行级评审意见；没有有意义的 diff 时，`ocr scan` 直接整库/整目录审计；内置规则覆盖空指针、线程安全、XSS、SQL 注入；结果可出 JSON 进 CI。
- **为什么现在推**：今日 GitHub 日榜第 1（单日 +215 星），约 50.7K star（Apache-2.0）；2026 年 5 月开源，阿里内部已跑两年、服务数万开发者。项目方自家基准称：同模型下约 1/9 的 token、精度与 F1 高于 Claude Code，但召回更低（项目方口径：宁可少报噪音，也不求全报）。和你库里已有的 codex-security（OpenAI 官方，11 月 12 日已推）是同一条"agent 审代码"赛道的不同打法：那个是全套扫描+打补丁，这个是轻量 CLI、只审不改，还能把评审委派给宿主 agent（不走自己的模型账单）。
- **安装 / 获取**：https://github.com/alibaba/open-code-review ；`npm install -g @alibaba-group/open-code-review`，然后 `ocr config provider` / `ocr config model` 配端点；或用委派模式（`ocr delegate`）把评审交给已有的 Claude Code / Codex，不用另配 API key。上手：先 `ocr review --preview` 看它会审哪些文件，再 `ocr review`；整库审计用 `ocr scan --path src/auth`。有 Claude Code / Codex 插件与可移植 skill。
- **适用工具**：Claude Code / Codex / Cursor / OpenCode 等（CLI + 插件 + skill）；模型端点须支持原生工具调用，兼容 OpenAI / Anthropic 协议，也可接本地 Ollama / vLLM。
- **⚠️ 权限提醒**：评审要把 diff 与代码片段发给所配的 LLM 端点（FAQ 原话）；先确认端点可信、别把含密钥的仓库直接交给陌生端点；须 Git 2.41+ 与 Node.js 18+。

### 2. backnotprop/plannotator——给 agent 的计划与 diff 开一个浏览器批注面，批完点发送回传给 agent

- **一句话能力**：本地跑的浏览器评审面：agent 出计划、文档、HTML 或 diff 后，自动在浏览器里打开，你直接在上面划线、写批注，点发送就把结构化反馈送回出活的那个 agent 会话；新出的 Inbox 把多 agent 的提问、决定、原型收在一个窗口里，不用一直挂着等 agent。
- **为什么现在推**：今日 GitHub 日榜上榜（单日 +108 星），约 10.5K star（双 Apache-2.0 / MIT）。正对着你的用法——Codex 团队"大总管拆解、多角色并行"时，最缺的就是"人怎么快速审计划、把意见准确送回去"的环节：现在是终端里看计划、口头回意见；Plannotator 把这一步变成浏览器里划线批注、自动回传。还支持 Git / GitButler / Jujutsu / Perforce 与 GitHub / GitLab 的 PR/MR 评审。
- **安装 / 获取**：https://github.com/backnotprop/plannotator ；文档 docs.plannotator.ai/open-source/start/installation；Codex 里用 `!plannotator review` / `!plannotator annotate file.md`，Claude Code / OpenCode 走插件，`plannotator inbox` 开 Inbox。
- **适用工具**：Claude Code / Codex / Copilot CLI / Gemini CLI / OpenCode / Kiro 等；Inbox 也接 Grok Bot、Muse 等个人助手（走 MCP）。
- **⚠️ 权限提醒**：本地优先、不收集遥测，计划与批注默认不出本机；但每个评审面加载时都会向 GitHub 查最新版本（无关闭开关），URL 批注默认走 Jina Reader 拉取页面——严格内网或涉密环境先看 README 再装。
