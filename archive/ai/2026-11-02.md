### 1. LongCat-2.5（美团，11 月 1 日晚–2 日凌晨正式发布）
- **含义**：美团 LongCat 系列的新一代原生多模态模型，定位不是"问答更强"，而是**长程 agent 任务**：在终端、浏览器、桌面软件、表格、设计工具里跨多步执行，改复杂代码库、从头做完一个完整软件项目。上一代 LongCat-2.0 是 9 月的 API 预览，这次是正式版：长cat.chat 与 LongCat API 已可用，GitHub / Hugging Face 发布在来源里写的是"计划随后跟进"，不是今天已上线。
- **来源与口径冲突（先说清楚，再读数字）**：TechNode（11 月 2 日 04:32 UTC 发稿）与 Longbridge 转述的美团公告一致：总参数 1.6 万亿、每 token 激活约 480 亿、原生视觉理解 + agent 编程能力较 2.0 增强。但 aiaffairs 同日提醒：**这组参数数字有争议**——OrcaRouter 10 月 29 日指出，预览期的 1.6T/48B 数字来自 LongCat-2.0 的模型卡、被沿用到了预览版上。按"注意事项"（引用参数规模以原文为准、不自己加零），本条把 1.6T/48B 写为"美团公告口径、另有来源质疑其沿用自 2.0"，不等它当已证实事实。
- **厂商自报的成绩（未独立验证）**：Terminal-Bench v2.1 为 88.4（2.0 为 70.8）、AutomationBench 51.8、BrowseComp 91.9；但同一张厂商榜单里 Program Bench 只有 25.5，低于榜首的 37——不是全榜通吃。训练侧的说法是：用更长的任务轨迹（含失败尝试转成的训练任务）+ 大规模强化学习，4-bit 权重与激活针对国产芯片做了推理优化。
- **价格（平台整理口径，限时折扣）**：APIYI 按 LongCat API 平台整理的限时价为输出 $1.20 / 百万 token、缓存未命中输入 $0.30 / 百万 token、缓存命中输入 $0.006 / 百万 token，价格可能变动，以官方平台页为准。
- **为什么出圈**：它是 10 月"开源/低价 agent 档"（DeepSeek V4.1-Flash、GLM、MiniMax M3.1 Flash、Kimi K3.1 Pro）之后，中国厂商在"长程编码 agent"上正面拼榜单的一步；且与 11 月 1 日日报的 DeepSeek Super-agent 原型呼应：一个讲"常驻、少打扰人"的组织方式，一个讲"一口气干完长任务"的模型能力——两条线拼起来才是"不用盯的编码 agent"。
- **与你的关联**：你用 Claude Code / Codex 跑多工具并行，LongCat-2.5 值得当"便宜的长任务备选"试一次：来源称它支持 Claude Code、Codex、Hermes 等 agent 工具接入。先拿一个非关键的小项目跑完整流程（从改代码到出 PR 的全链路），别只跑单轮问答测分；等 GitHub / Hugging Face 权重真正上线后再谈本地部署——今天按"API 与网页可用、权重未上线"理解。

### 3. 新词：Loop Engineering（11 月 2 日，The Hindu）
- **含义**：从"提示词工程"往后一步的工种名：不再是"写一句好提示、拿一个好答案"，而是**设计 agent 循环本身**——什么触发一次运行、agent 能碰什么、能花多少钱、什么时候必须停下来问人。The Hindu 的定义句很直白：开发者现在是"编排 AI 系统，让它自己写、测、修代码"，而不是手写每一行。
- **来源**：The Hindu 11 月 2 日教育版文章，标题直译为"为什么 Loop Engineering 是印度学生不能忽视的新技能"。它还给了下一站：多 agent 协作时，Loop Engineering 演变为 **Graph Engineering**——设计的不再是一个循环，而是一张分工网络（规划、研究、写作、验证各一个 agent）与它们之间的工作流。
- **为什么出圈**：它把过去一个月日报里反复出现的现象取了个名字：DeepSeek Super-agent 的 Router/Worker 与"只在该说话时说话"、Rulesync 的 fail-closed hooks、OpenShell 的 runtime 策略——全是"循环怎么设计、边界画在哪"的问题，而不是"提示词怎么写"的问题。提示词正在被工具内置消化，循环设计正在变成新的手艺。
- **与你的关联**：你已经在做的事（多工具并行、规则同步、给 agent 定权限）就是 Loop Engineering 的日常版——下次给 agent 排活时，按这篇文章的清单自查一遍：触发条件、能碰的目录与凭证、花多少钱封顶、什么情况下停下来问你。这四个问题答不上来，循环就不该无人值守跑。
- 出处：https://www.thehindu.com/education/why-loop-engineering-is-the-new-skill-indian-students-cant-afford-to-ignore/article71628676.ece

## 五、今日好用开源技能

### ① claude-mem：给 Claude Code / Codex / OpenCode 等 agent 装一个"跨会话记忆"，换会话不用重讲项目
- **一句话能力**：用生命周期 hooks 自动记录每次会话的工具使用与观察，压缩成可检索的记忆，下个会话自动注入相关上下文；并提供 `search → timeline → get_observations` 三层 MCP 搜索（先拿 50–100 token 的索引、再按需取详情，厂商口径称约省 10 倍 token）。
- **为什么今天推（补位经典，不是今日新发）**：2025 年 8 月 31 日建仓的老项目，今日直接核查仓库时 110,280 星、9,619 fork、3,834 commit、Apache-2.0，本周 GitHub Trending 档案列在第 4 位；且它与你 10 月 17 日已入库的 ai-memory 不重复：ai-memory 是以 git 备份的 Markdown wiki 为事实来源的共享记忆，claude-mem 是 hooks 自动捕获 + 压缩 + MCP 回查的会话记忆——一个是"你写下来的 wiki"，一个是"它自己记下来的会话"。你多工具并行、长会话会退化（全景表里 GLM 一节已有此提醒），跨会话记忆正好补"换 agent 就失忆"的缺口。
- **安装 / 获取来源**：https://github.com/thedotmack/claude-mem（已直接打开仓库核实：公开、Apache-2.0、主分支含插件目录）。Claude Code 插件市场：`/plugin marketplace add thedotmack/claude-mem` 再 `/plugin install claude-mem`，重启 Claude Code；或 `npx claude-mem install`（按 IDE 加 `--ide opencode / antigravity / omp` 等）；注意 `npm install -g claude-mem` 只装 SDK、不注册 hooks，别用它当安装方式。
