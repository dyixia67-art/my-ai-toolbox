### 1. ETH 被证伪？OpenAI 与 Anthropic 同日宣称，Lean 过了关、学界还没点头
- **含义**：ETH 即 Exponential Time Hypothesis（指数时间假设），1999 年提出的猜想：判定一个布尔公式能否被满足（3-SAT 问题）不可能在"次指数时间"内完成。几百篇论文把它当作"如果 ETH 成立，则……"的条件硬度前提——图论、计算生物、数据库、计算几何都用过它。它不是 P≠NP 本身：ETH 倒了，P≠NP 仍可能成立。
- **两家各说什么（均为 10-26 官宣，北京时间 10-27/28 扩散）**：
  - OpenAI：内部模型 10-16 写出自然语言证伪、10-17 在 Lean 证明助手里形式化；同期还宣称证明了 Sogge 1991 年局部光滑猜想（每维都成立，顺带解决 Kakeya 猜想与 Stein 限制猜想）与四维量子场论（含 QCD、纯 Yang-Mills）的存在性证明。三个结果的公开策略各不相同：数学与计算机结果的 AI 原稿 + Lean 证明已公开；物理结果暂不公开，由诺贝尔奖得主 David Gross 牵头的团队自己重写。
  - Anthropic：内部研究 Claude 模型也给出 3-SAT 的次指数算法（2^o(n) 时间）与 Lean 形式化，结论同样是 ETH 为假；Anthropic 自述该结果是"纯渐近"的——只讲变量数趋大时增速，不等于马上能跑得更快。
- **关键区分，别写错**：
  - Lean 机器核对通过 ≠ 学界认证。Lean 只保证形式化陈述的每一步逻辑无误，不保证"这个陈述就是原猜想"或"它在实践中有用"。OpenAI 自己也提醒：把结论变成实际加速"需要大量后续研究"。
  - 形式化版本与论文 headline 并不逐字相同（二手核对指出：Lean 版证明的指数界比手稿最 sharp 的界稍弱，但两者都仍是次指数，所以 ETH 结论不受影响——引用时要带这个限定，别把手稿数字当成 Lean 已证数字）。
  - 密码学影响：Ryan Williams 转述，OpenAI 已检查并"有理由相信"该结果不意味着现有密码系统被攻破；Anthropic 的算法是渐近结论，不是多项式时间算法，别写成"3-SAT 被破解了"。
- **为什么走红 + 验证机制本身就是新闻**：OpenAI 不自己领学术功劳，做法是：把验证交给提出 ETH 的 Russell Impagliazzo、Ramamohan Paturi（UC San Diego）与 MIT 的 Ryan Williams 牵头的外部团队，并按对方要求公开原始数据、出资办研讨会；三位学者在公开信中明确"参与不等于认证"。另有 $5M 捐给 Simons Foundation（厂商口径）用于研讨会与后续项目。Anthropic 的独立同结论让这件事从"一家之言"变成"两家撞题"——但"撞题"仍不是"证实"，外部核查按报道口径"需要数月"。
- **与你的关联**：你用 Codex / Claude Code 时，真正该带走的不是 ETH 本身，而是这个工作流——**"AI 产出 + 机器形式化核对 + 独立第三方复核"**三段式。以后你让 agent 出结论、改关键代码时，照搬这套：先让它给出可核查的产物（测试、证明、diff），再由另一方（另一模型、测试集、人工）独立验，别只看它自己说的"我对了"。
- 出处：https://news-insight-ai.web.app/en/news/20261028_ai-news-daily（10-28 日报汇总，含三结果与验证安排）· https://dealroom.co/news/167089-openai-says-its-ai-disproved-a-core-computer-science-assumption-gives-5m/（10-27，$5M 与"参与不等于认证"）· https://www.unite.ai/openai-says-its-models-produced-three-proofs-in-math-cs-and-physics/（10-26 官宣细节，10-16/10-17 时间线）

### 2. Genie 4：Google 世界模型第一次"自带声音"，还能边跑边改
- **含义**："世界模型"不是视频生成器：视频是"拍一段给你看"，世界模型是"造一个地方让你走进去"——键盘移动视角、打字改天气/加人/加物，世界实时接着演。Genie 4 是 DeepMind 10-27 官宣的第四代。
- **这次新的三点（DeepMind 官宣）**：
  - 原生音频：音乐、环境声、角色对话与画面同一模型同步生成，不是事后配音；这是 DeepMind 首个实时带音频的世界模型。
  - Gemini 在环内当"导演"：Gemini Omni 锚定物体外观与行为的真实感；Gemini 3.8 Flash 在循环内当引导智能体——拆解目标、逐帧检查步骤是否达成、维持连贯。机器人方向的演示是 Genie 4 + Gemini 4 Argon 模拟 Apptronik Apollo 人形机器人下跳棋。
  - 可用状态：先给受信任测试者做研究预览，随后是 Google AI Ultra 订阅者的 Project Genie、Gemini API 与 Google AI Studio 的早期合作伙伴；所有生成音视频带 SynthID 水印。
- **时长与限度（注意口径分层）**：二手报道（TechCrunch / The Verge 转述）称连贯场景约 2 分钟，是 Genie 3 约 1 分钟的两倍；DeepMind 自己在官宣中承认的限度是：长会话、多次复杂改动后，细节与物体恒常性仍会漂移。**2 分钟是转述口径，不是官宣规格**；分辨率、帧率、API 定价官宣未公布，别补数字。
- **为什么走红**：世界模型从"只能看"到"能听、能对话、能改"，离"用一句话搭一个可玩原型"的距离又近了一步——游戏原型、机器人训练环境、交互体验草图是它最先落地的三处。但它仍是"草图板不是引擎"：漂移问题没解决前，别拿它当可交付的成品世界。
- **与你的关联**：你玩 AI 生图/视觉设计时，Genie 4 值得当"动态草图"工具记一笔：静态图用 Midjourney 那一路，可交互的场景草图以后看 Genie 这条线；等它进 Project Genie / API 后再实测，别为研究预览排队焦虑。另注意官宣里同时出现 Gemini 3.8 Flash 与 Gemini 4 Argon 两个名字——全景表（10-16 快照）只写了 Gemini 4 Argon，**3.8 Flash 是 11 月 1 日刷新时要核对的新增型号名**。
- 出处：https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/（DeepMind 10-27 官宣）· https://hotfixdaily.com/issues/006/（Hotfix Daily #6，10-28，定位为"草图板不是引擎"）

### 3. Entire：前 GitHub CEO 另起炉灶，PR 换成 Trails——"评审跟不上生成"终于有人换制度
- **含义**：Entire 是前 GitHub CEO Thomas Dohmke 10-26 推出的 Git 兼容开发平台（Git forge），定位是"为 agent-人类协作从头做的代码托管"。核心判断一句话：agent 写代码的速度已经超过人逐行审 PR 的速度，旧制度本身成了瓶颈。
- **Trails 是什么**：替代 PR 的评审制度。每次 push 后，多个 AI agent 按可配置标准（安全、质量等）给改动打分，开发者看的是评分仪表盘（Dohmke 的比喻：像飞行员的平视显示器），而不是逐行 diff；团队仍可设门槛——人工签核、自动化测试通过后才合入，agent 发现问题后可循环修复。另有 Continuous Memory：把每次改动背后的上下文存进仓库可检索的记忆，供后续 agent 查"当初为什么这么改"。
- **厂商口径与未验证数字（必须分开写）**：种子轮 $60M、估值约 $3 亿（多家二手报道一致，未见官方融资公告原文）；分布式 Git 托管"比 GitHub 快 89 倍"、Continuous Memory"省 token 高达 71%"——**均为厂商口径，未独立验证**，别当实测结论。时间点值得记：发布在 GitHub Universe（10-28/29，旧金山）开幕前两天，针对性很明显。
- **对岸的动静（同一周的 incumbent 回应）**：GitHub 并非无动作——Copilot assisted permissions 10-26 已 GA（模型先判"明显安全"的请求才免确认，介于全自动与全人工之间，企业可禁用）；Copilot SDK 的 server-to-server 认证 10-27 进公开预览（agent 不再绑个人账号，改用组织拥有的 GitHub App 身份+短期 token，账单与审计归组织）。两件事拼起来看：**Entire 是换赛道，GitHub 是给旧赛道加护栏**，路线不同。
- **与你的关联**：你用 Codex / Claude Code 时迟早会撞上同一个瓶颈——agent 一次推几十个改动，你审不过来。Entire 的思路可以直接借用，不必马上迁移平台：给自己的评审立三条——agent 改动必须附带可运行的测试结果、关键改动必须人工签核、每次改动留一句"为什么这么改"的记忆。等它对个人开发者/开源维护者的开放细节更明确后再评估迁移成本，托管地、定价今天都还没说清。
- 出处：https://www.geekwire.com/2026/former-github-ceo-launches-rival-platform-built-for-ai-coding-agents/（GeekWire 10-26，Trails 与 Dohmke 表述）· https://hotfixdaily.com/issues/006/（Hotfix Daily #6，10-28，"现已向所有开发者开放"口径）

### 4. Oracle × OpenAI：企业软件长进 ChatGPT，但 Workspace 还在"开发中"
- **含义**：10-27 Oracle AI World（拉斯维加斯）宣布的扩大合作，四件套：Oracle AI Workspace、Oracle AI Security Mesh、Oracle App Composer、Oracle AI SMB Bundle。核心是把 OpenAI 的模型、ChatGPT、Codex 接进 Oracle 的应用、数据与云基础设施。
- **四件套分工与状态（别把"宣布"写成"已上线"）**：
  - Workspace：通过 ChatGPT 插件接 Fusion Applications、NetSuite、Oracle AI Database、OCI，员工用一句话查财务/采购/规划数据、走已批准的工作流；**OpenAI 自己注明"仍在开发中"，个别插件已可安装、完整体验未到**。权限口径是关键：仍走组织原有权限与审批链，"能看"不等于"能批、能改"。
  - Security Mesh：托管服务，用 OpenAI 网络安全模型找漏洞、排优先级、修复再测，Oracle 管测试环境；可用状态与定价公告未说明。
  - App Composer：员工用 Codex 等工具在已批准数据上搭企业应用，Oracle 在 OCI 上管部署运维。
  - SMB Bundle：限量申请制，含 ChatGPT、Codex、OCI、NetSuite QuickStart，含每年 $12,000 OCI 额度、最长 3 年（厂商口径，附 eligibility 条款）。
- **今天就能用的部分**：美国 Oracle 客户可通过 Oracle Marketplace、用现有采购流程与符合条件的 Oracle Universal Credits 购买 OpenAI API、Codex、ChatGPT Work 的访问——这是四件套里唯一明确"现在可买"的通道，且是美国范围。
- **厂商自报的内部采用数（未独立审计）**：Oracle 内部 130,000 活跃 ChatGPT 用户、95,000+ 活跃 Codex 用户；招聘团队用 ChatGPT Work 做市场研究从 2–4 天压到 15–20 分钟。**这是 Oracle 自家案例，别外推成所有客户的收益**。
- **与你的关联**：Uber 全员上 ChatGPT Work（10-22 讲过）+ Oracle 这次，拼出同一趋势：**agent 正在从"聊天框"长进"企业系统里"**，而每一次落地的真正门槛都不是模型能力，是权限、审批、审计能不能原样映射过去。你以后给自己的 agent 接任何"能改东西"的系统时，先问这句：它动的是只读查询，还是会写回？写回要谁批、留什么日志？

## 五、今日好用开源技能

### ① NVIDIA SkillSpector —— 装技能之前，先让扫描器过一遍（10-27 开源雷达点名，非今日新发）
- **一句话能力**：专扫 AI agent 技能的安全扫描器：装 Claude Code / Codex / MCP 技能之前，先查它有没有提示词注入、数据外泄、提权、供应链投毒、记忆投毒、MCP 工具投毒等 71 种模式（17 类），输出 0–100 风险分与严重度建议。
- **为什么今天推**：你这半个月已收了 20+ 个技能进库，"装之前先验货"本身就是刚需；SkillSpector 的研究底数值得记一句——它分析的 31,132 个技能子集中，26.1% 含漏洞、5.2% 疑似恶意意图（README 原文，NVIDIA 研究口径）。它还是 NVIDIA Verified Skills 管线里的门禁，过了才进官方技能目录——等于把"要不要装"从凭感觉变成可复现的检查。
- **安装 / 获取来源**：https://github.com/NVIDIA/SkillSpector（Apache-2.0；建仓 2026-03-21；检索时约 22,918 stars、1,981 forks；README 已核对）。安装（README 原文，uv 路线）：`uv tool install git+https://github.com/NVIDIA/skillspector.git`；无 Python 时可用仓库自带 Dockerfile 本地构建。基本用法：`skillspector scan ./my-skill/`（可扫目录、单个 SKILL.md、Git 仓库、zip）；`--format json/markdown/sarif` 可出报告进 CI；另有 MCP server 模式与 Pi / OpenCode 扩展。
- **适用工具**：Claude Code、Codex CLI、Gemini CLI 等 SKILL.md 兼容 agent，以及 MCP 客户端（可扫 MCP 注册表快照对比）。
- **一句话上手**：先拿你已经装过的一个技能跑 `skillspector scan <技能目录> --no-llm`，看它的风险分与报告格式是否对得上你的直觉——对得上，再把它写进"装新技能前必跑"清单。
- **安全提醒（必读）**：① 默认静态扫描在本地跑，但**可选的 LLM 语义分析会把技能内容发给模型服务商**，扫含私密内容的技能时先用 `--no-llm`；② 扫描器本身要读技能文件，扫来路不明的仓库时先在副本/容器里跑，别直接对唯一工作目录扫改动类操作；③ 扫描通过 ≠ 绝对安全：它是 71 种已知模式的检查，README 自身也列了局限性，涉及凭证、资金、写库的技能仍要人工读 SKILL.md 再装；④ 安装会拉取第三方开源组件，装前看一眼 README 的开源软件提示。
