### 1. OpenAI 抢 Anthropic 客户：不是官宣降价，是谈判桌上的"价格战"
- **含义**：The Information 10-24/25 报道（经多家二手转述，OpenAI 与 Anthropic 均未就此发表可查的官方回应）：OpenAI 以大幅谈判折扣争取 Anthropic 的企业客户，核心案例有三家——
  - **Replit**：OpenAI 给出年合同超 1 亿美元、折扣超 30% 的条件；背景是 Anthropic 不再延续 Replit 此前的折扣（除非承诺更高消费）。Replit CEO Amjad Masad 10 月中旬已在台上说不再与 Anthropic 合作、OpenAI 成默认模型；随后又澄清 Replit"仍是模型中立"，用户仍可选 Claude——**默认位变了，但不是彻底断供**，这个区分要留住。
  - **Rippling**：CEO Parker Conrad 称其编码工作量中 OpenAI 占比由 16% 升至 52%，Anthropic 由 57% 降至 18%。
  - **DataCamp**：CEO Jonathan Cornelissen 称 OpenAI 定价使其成本降 80%–90%；另一路转述称 Codex 折扣为 40%——**两组数字口径不同（总成本降幅 vs 单项折扣），不要混成一个数**。
  - 另有一家资产超 70 亿美元的美国银行：ChatGPT 席位翻倍至 500 人且不加价，单用户价低于 7 美元，对照常规价 20 美元以上。
- **为什么走红**：Anthropic 公开 S-1 的传闻时间点就在眼前（见产品更新），这时大客户出来谈"便宜了多少"，对 IPO 叙事最不利；更深一层是信号：**在应用层，两个模型已接近到价格可以决定胜负**——Replit 换默认的报道里没有出现"Claude 写代码输了"的基准证据，触发点是折扣停了。模型差异仍在，但 harness、重试、脚手架把差距磨平后，账单就成了决胜项。
- **与你的关联**：这是"便宜 worker 档"继续变厚的另一面——GPT-6 Luna 这类低成本线（见下文 Decisions API）让 OpenAI 有空间打折；你选模型时，"默认模型"与"可替换模型"是两回事：凡是能一键换模型的环节（Codex / Claude Code / API 调用），都要留好切换成本低的姿势，别被一家默认位锁死。注意：**这不是 OpenAI 公布的新价目表**，是谈判个案，不要按"降价 90%"去算自己的账——90% 是 DataCamp 一家的总成本降幅口径。

### 2. Kimi K3.1 Pro 开源前的"降网攻"：权重还没放出来，刹车先装好
- **含义**：Moonshot 10-24 随 K3.1 Pro 发布同步说明（Reuters 10-24/25 报道）：为 11 月 4 日前的权重开源做准备，已从中期训练语料中删掉网攻相关数据、从强化学习任务中滤掉网攻任务，但保留通用编码能力。官方原话："We aim not to release open weights that would extend the absolute frontier of cyber capability"（不打算放出会把网攻能力前沿再往前推的开源权重），并称将"逐步"提高开源权重中的网攻能力上限。
- **数字（均为 Moonshot 自家基准，未经独立验证）**：自家 xdev-bench-hard（真实软件漏洞利用，pass@3）上，未做删减的检查点得分 90.5%，最终发布版 81.0%，仍远高于 K3 的 33.3%，且低于另一路转述中 DeepSeek-V4.1-Flash 的 85.7%。**读法：降了 9.5 个百分点，不是清零**——删数据是"调低旋钮"，不是"上锁"；且权重一旦散出去，官方就管不住后续微调，这是开源与闭源托管的根本区别。
- **为什么走红**：与昨天"产品先上、权重待开"拼成完整故事——开源放量与网攻风险是同一枚硬币的两面；背景是中国上周拟议的出口管制草案（拟禁 AI 恶意软件生成、限制 AI 辅助漏洞发现工具，仍在征求意见），Moonshot 这一刀既是安全表态，也是合规前置。
- **与你的关联**：11 月 4 日权重一开，K3.1 Pro 就是可本地跑、可魔改的 3 万亿级模型；但"网攻能力被调低过"意味着拿它做安全审计、漏洞复现时，别默认它与托管版能力一致——防御性用途（给自家老系统找漏洞）仍在，但别指望它当全功能渗透工具。11 月 1 日全景表刷新时，Kimi 条目应记"产品已上、权重待 11/4 前开放、网攻数据已删减"，三句缺一不可。

### 3. 补漏：Claude Duet——第四个"不用你盯着"的常驻 agent（10-21 发布，本日报此前漏讲）
- **含义**：Anthropic 10-21 开放研究预览（waitlist）：Claude Duet 不是聊天框，是主动 agent——每天早上先给你一份跨应用简报，白天每隔几小时巡查已连接应用，有事才找你；你交代的任务在它自己的云端虚拟机 + 浏览器里继续跑，你手机关机也不停。底层是 Claude Opus 5.5，连接器与插件超 6000 个（厂商口径，含 Gmail、Slack 等），沿用你 Claude 账号里的记忆、技能与已连接应用。
- **刹车设计（这才是它与前三者的对比点）**：发消息、付款、签文件、删东西之前必须先经你批准；证券交易与账户间资金划转直接禁掉，批了也不行；买东西走 Stripe Link 或 Shop Pay，Link 用虚拟卡号、不暴露真卡号。代价是：**用量计入你原有 Pro/Max 套餐额度**，后台巡查会悄悄吃掉你的额度。
- **门槛（先别急着试）**：目前仅限美国 Pro / Max 订阅用户排队，iOS、Android 与 claude.ai 可用；Team / Enterprise 不在首批预览里。也就是说国内用户今天还用不上，看的是"形状"不是"入口"。
- **为什么补**：它是 2026 年 8–9 月那波常驻 agent 的第四块拼图——Meta Muse（9-08）、OpenAI Dots（9-29）、xAI Grok Bot（8-11 beta），再加 Duet；全景表 10-16 快照里"交代完不用盯"一行只有 Dots、Muse、Grok Bot，**11 月 1 日刷新时 Duet 应补进第四个**。四个产品的共同形状正在收敛：主动巡查 + 云端续跑 + 动钱动消息前必经批准——这与 10-22 的 1Password for Agents（凭证模型看不见）是同一套"管住主动 agent"的解法。

### 4. 补漏：AWS Infinity——agent 不是"一个接一个跑"，是"几万个一起等"（10-23 发布）
- **含义**：AWS 与 UC Berkeley 10-23 开源 Infinity（Apache 2.0，Hydro 项目）：一个 agent runtime，核心是"无栈协程"——每次工具调用就是一个挂起点，agent 闲下来时只剩对话历史占内存，不占任务栈、不占连接；同一批线程可承载大量闲置 agent，同一份 agent 代码可在本地进程与 serverless 上跑；合成工具调用用来在模型 API 已有的结构里呈现异步事件与父子 agent 间消息。
- **数字要慢读（防标题党）**：AWS 的测试是在单线程服务器级 AMD EPYC 上、用模拟模型跑 8 万个 agent，每闲置 agent 约 100KB 内存（主要是对话历史）。**这测的是"记住对话"的成本，不是 8 万次真实模型推理，也不是树莓派实测**——真实 agent 的历史里还有工具输出、文件内容、报错日志，1MB 历史的话 8GB 内存只能撑约 8000 个。标题里的"几万个"要还原成"每闲置 agent 约 100KB（测试条件）"才可信。
- **为什么走红**：与本周三条线拼成一张图——Daytona（10-20 独角兽：把隔离电脑租给你）、NVIDIA OpenShell（runtime 层划边界）、Infinity（runtime 层省内存、撑并发）：agent 落地真正的瓶颈正在从"模型够不够聪明"转向"几千几万个 agent 同时在线时，内存、隔离、账单怎么算"。
- **与你的关联**：你今天在 Windows 上跑一两个 Codex / Claude Code 还碰不到这个量级；但一旦开始"一堆 agent 并行跑测试、跑爬虫、跑多仓库任务"，闲置成本就是第一笔账——Infinity 的思路（闲置只留历史）值得在选编排工具时当一把尺子量：看它闲置时到底占多少。
- 出处：https://aws.amazon.com/blogs/opensource/introducing-infinity-a-runtime-for-extreme-agent-concurrency/（AWS 官方博客 10-23）· https://alfw.ai/article/aws-infinity-75000-agents-pi-claim/（10-24，对测试条件的拆解）

## 五、今日好用开源技能

### ① Hallmark —— 治"AI 味页面"的设计 skill（补位经典，非今日新发，今日 GitHub Trending 上榜）
- **一句话能力**：Together AI 出品的反"AI 味"（anti-slop）设计 skill：不给你换个配色了事，而是先定页面骨架与主题，再用真实浏览器跑一遍"机器味"检查（标题上都顶个小标签、通篇千篇一律的 hero + 三卡片 + CTA、假表单等），最后由一个全新上下文的评审员拍板——目标是让 agent 生成的页面"像两个不同网站，而不是同一模板换颜色"。
- **安装 / 获取来源**：https://github.com/Nutlope/hallmark（MIT；2026-05-19 发布，今日检索：10-25 当天 32,133 stars、GitHub Trending 上榜——为第三方转述的当日快照，非实时核验）。安装：`npx skills add nutlope/hallmark -g`（需 Node 18+；不加 `-g` 则只装当前项目）。命令：`/hallmark <需求>` 新建页面、`/hallmark redesign <路径>` 保留文案重搭结构、`/hallmark audit <路径>` 只出问题清单不动手；另有 `hallmark study` 可从截图/链接抽设计 DNA。
- **适用工具**：Claude Code、Codex、Cursor、OpenCode、Gemini CLI 等（Skills 兼容 agent）。
- **一句话上手**：先只跑 `/hallmark audit` 审你手头一个现成页面，看它挑的毛病是不是你平时也烦的那些，再决定要不要让它接管新建页面。
- **安全提醒**：skill 本身是提示词 + 工作流，会让 agent 在你的项目里写文件、用真实浏览器跑检查——先在非主力分支试，生成的页面上线前自己过一遍文案与链接，别让"检查通过"代替你审内容。
- **为什么今天推**：你对视觉质感的要求高（曾直接否决红底通栏大字海报），Hallmark 治的正是"AI 一眼味"——它不替你做审美决定，而是把模型最爱滑回去的默认套路挡住；且它是 5 月就已发布的经典，今日上榜才补推，不算追新凑数。
