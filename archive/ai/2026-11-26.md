### 1. FCC 批 SpaceX Starmind：一百万颗"轨道数据中心"卫星，算力第一次拿到上天批文（11 月 25 日）

- **发生了什么**：美国联邦通信委员会（FCC）11 月 25 日批准 SpaceX 的 Starmind 星座——最多 100 万颗非静止轨道卫星，在低地球轨道（500–1,002 公里）组成轨道数据中心（ODC），用太阳能跑 AI 计算、把结果传回地面。FCC 称这是美国历史上第一次批准"太空数据中心星座"。
- **时间表是硬的**：首颗卫星须在 2033 年 11 月前入轨运行，10%（10 万颗）2035 年 11 月前，50% 2038 年 11 月前，全部 2040 年 11 月前；错过任一节点牌照作废，牌照期 15 年。SpaceX 申请时要到 2,000 公里高度，FCC 只批到 1,002 公里，600 公里以上须另交最终轨道碎片方案才能飞。SpaceX 首席财务官 Bret Johnsen 上周称，首批轨道数据中心计划 2027 年发射、2029 年前扩大。
- **为什么出圈**：算力短缺的叙事第一次从"抢电、抢卡"讲到了"抢轨道"——太空太阳能被说成是绕开地面电力瓶颈的答案。FCC 主席 Brendan Carr 的原话是"美国正在引领世界进入超级智能时代"。Starmind 也是马斯克 6 月 SpaceX IPO 路演的重要卖点之一（Morningstar 口径）。
- **另一面**：科学家普遍怀疑——芯片散热（真空里没法靠空气散热）、轨道碎片、天文观测干扰。美国天文学会、Viasat、亚马逊 Kuiper 都曾要求 FCC 否决；FCC 按 10 月新规未再做《国家环境政策法》环评。FCC 自己也未对"这门生意是否划算"表态。
- **与你的关联**：先当基础设施叙事看，不当技术定论——一颗星都还没上天，2033 年才是第一个交卷日。但"算力往天上走"一旦成为大厂的第二条路线，地面数据中心的电价、审批与选址逻辑都会跟着变；你工具箱里收的本地部署、便宜芯片路线，长期看是同一道"算力从哪来"的题的另一面。

### 2. Google Workspace MCP 服务器 + CLI 正式 GA：2027 年 2 月 1 日起，agent 不走 MCP 就别想进 Workspace（Google，11 月 24 日）

- **发生了什么**：Google 11 月 24 日宣布 Workspace MCP 服务器与官方 Workspace CLI 正式 GA，覆盖 Gmail、Drive、Docs、Sheets、Slides、Calendar、Chat、Tasks（Keep 随后到）。这是 Google 托管的 MCP 服务器，agent 不用自己写集成代码，直接调用现成工具。
- **强制条款**：从 **2027 年 2 月 1 日**起，AI agent 或类似工具访问 Workspace 数据**必须**走 MCP 或 CLI，直接调 Workspace REST API 的 agent 将被限制在 Standard Tier 用量额度内（无论是否选了 Scaled tier）。新的《Workspace AI Tools Addendum》同日生效：不许永久存原始数据、不许拿数据训模型、不许超期保留衍生数据、不许爬接口。
- **计费**：分两档——Standard tier 免费、有公开用量上限；Scaled tier 面向高用量项目，**2027 年 4 月 1 日**起超出每日免费额度的 API/MCP 用量开始计费（Scaled tier 下 MCP 请求从第一次起就计费）。另有 Agent Gateway 与 Agent Registry：agent 拿独立身份、不用共享长效密钥，权限、确认、提示词筛查、审计日志自动进请求链路。
- **细节**：OAuth 客户端须在 Google Auth Platform 里勾选"Use this client for an AI-powered agent"；自 11 月 11 日起，未标记为 agent 的客户端请求会被 Workspace MCP 服务器拒绝。
- **与你的关联**：这是本月 MCP 主线迄今最硬的一块——10 月 6 日 Snyk MCP Governance（管住）、10 月 7 日 NVIDIA OpenShell（runtime 层）、10 月 6–7 日 Atlassian AMP（组织协作层）、11 月 24 日 Anthropic Skills over MCP（服务器反过来教 agent），今天 Google 把"必须走 MCP"写进了全球最大办公套件的强制条款。你的 Codex 团队以后接 Gmail/Drive/Calendar 这类办公数据，MCP 是唯一合规入口，REST 直连的路 2027 年 2 月 1 日就被限流；同时这也是你团队"高风险动作先过人"流程的现成参照——Google 的做法是确认、筛查、审计全部进请求链路。

### 3. Anthropic：Claude 用三个月把自家 Messages API 从 Python 迁到 Rust，CPU 省约 70%——难的不是写代码，是验代码（Anthropic 工程博客，11 月 25 日）

- **发生了什么**：Anthropic 11 月 25 日发工程博客《Migrating our Messages API to Rust》，讲 Claude 如何把 Messages API（Claude API、Claude Code、Cowork 背后的同一条入口）从 Python 完整迁到 Rust。Claude 约一周写出核心请求路径的第一版，**2026 年 9 月**公开流量已切到 Rust，全程零停机、功能开发没冻结。
- **结果数字（Anthropic 厂商口径）**：每请求 CPU 省约 70%、内存省 80% 以上、Claude Code 用户收到首个 token 的中位时间缩短约 20%。背景是 API 流量从 2024 年初到 2026 年秋涨了约 1,800 倍；2026 年 5 月时 Claude 已写下 Anthropic 合并代码的 80% 以上。
- **真正值得看的是验证方法**：2026 年 4 月 Rust 版已通过约 98% 的集成测试，但一上真实流量，只有约四分之一的请求处理结果与 Python 版完全一致——测试能过不等于行为一致。Anthropic 的解法是把正在跑的 Python 版当"标准答案"：影子流量双跑、逐条比对差异，差异记录不含用户内容，分发给 Claude agent 去修；三层循环——内环（沙盒里秒级复现修 bug）、外环（生产环境验证修复）、记忆环（把犯过的错记下来，agent 下次不再犯）。Anthropic 自己的结论："验证，而非生成，已成为瓶颈"（Verification, not generation, had become the bottleneck）。
- **口径细则**：CPU 图表只覆盖一个区域，首 token 时间是 Claude Code 请求在较短周期内的数字；i10x 指出 Anthropic 未公布 agent 算力花了多少、写了多少 PR、耗了多少工时，Rust 代码也不公开。
- **与你的关联**：这是你 Codex 团队最值得抄的一篇。你的团队也是"agent 写代码"，这篇等于 Anthropic 把自家生产级迁移的完整打法公开了：生成便宜之后，瓶颈在验证；影子流量 + 差异指纹 + 三层修 bug 循环，是可以直接抄进你团队流程的形状。顺带一提，Claude 团队 6 月曾把约 60 条评审意见归纳成 CLAUDE.md 规则——你的角色文件也可以这样从实战里长出来。

### 6. Google Cogentic 一天发六篇数学论文：因式分解拿到 L[1/3] 无条件证明，但别当成 RSA 被破解了（Google Research，11 月 25 日）

- **发生了什么**：Google Research 11 月 25 日在 GitHub 一次贴出六篇数学论文，全部出自多智能体系统 Cogentic（跑在 Gemini 4 上）。每篇页面都写着"整篇论文与 Lean 4 形式化完全由 Cogentic 得出，除初始提示外无人干预"。领头的一篇声称：任意整数都能在 L_N[1/3, 105] 时间内完成因式分解，且**不依赖任何未证明的假设**——把 1992 年 Lenstra–Pomerance 证明过的 L[1/2] 界推进了一大步，追平了数域筛法（NFS）的 L[1/3] 量级。
- **先看细则再看标题**：常数 105 远大于数域筛法启发式分析里的约 1.92，且算法会把 210,000 以下的数直接试除——这是理论突破，不是更快的破解工具，**RSA 加密不受实际威胁**。另外五篇：确定性（不用随机）因式分解 L_N[3/4]、固定特征有限域离散对数（次拟多项式时间）、双人博弈 1/5 近似纳什均衡的多项式时间算法（MaximinKiteNE，此前多项式时间壁垒约 1/3）、log-rank 猜想的平方根壁垒、图重构。
- **口径**：六篇都只是贴在 GitHub 上，**未经同行评审**；承诺的 Lean 4 形式化称"将在 companion submission 中发布"，截至发稿尚未公开——在形式化放出之前，外部还无法逐行验算。别和同一天 Reddit 上"某实验室破解了多项式时间因式分解"的传言混为一谈，那条没有任何证据，Cogentic 声称的也不是多项式时间。
- **与你的关联**：这是"AI 做数学"同一条线的第三块拼图——11 月 21 日 Claude 辅助的黎曼证明（约 200 名数学家在审）、11 月 24 日 Anthropic 与 OpenAI 各自的 VP≠VNP 证明（均无人类数学家审过），今天是 Google 的 Cogentic 六篇。判断标准始终是同一个：Lean 形式化是否公开、同行是否复核——在那之前都只是"声称"。

### 7. Phala 终版事件报告：152,092 个经 OpenRouter 发往 DeepSeek 的请求，曾可被攻击者读取（Phala，11 月 23 日）

- **发生了什么**：Phala 11 月 23 日发布终版事件报告：10 月 21 日 02:25 至 11 月 1 日 02:03（UTC），经 OpenRouter 发往 Phala 实验性 DeepSeek V4 Flash 0731 部署的 **152,092 个请求**处于"可被攻击者读取"的状态，占同期 Phala 推理服务全部请求的 0.45%。Phala 的措辞是"at risk"（处于风险中），不是"已证实被读过"——但研究者 10 月 21–22 日埋的"金丝雀"假凭证确实在 11 月 7 日前被盗用过。
- **怎么出的事**：Phala 10 月 20 日在一台新 GPU 服务器上起了实验性部署，还没上齐生产级安全控制就接了 OpenRouter 的真实流量，网关也没校验服务器的 attestation；攻击者经主机管理软件（信任本机请求、不单独认证调用方）拿到权限，在模型虚拟机里装了 rootkit 读请求体。同一攻击者 11 月 5 日又拿到了 Phala Cloud 旧版密钥管理服务（KMS）的根密钥；两条路 11 月 6 日前都已堵上，基础设施重建、新 KMS 与新根密钥已启用。Phala 明确写了：TEE 硬件本身按设计工作，是外围控制掉了链子。
- **该做什么**：如果你在上述窗口期经 OpenRouter 用过 `deepseek/deepseek-v4-flash-0731`（未排除 Phala 的情况下），轮换当时请求里出现过的任何密钥、token、密码。OpenRouter 已通知受影响用户，其 11 月 22 日博客称 OpenRouter 自身未被攻破。
- **与你的关联**：这是一次教科书级的"实验环境接了生产流量"翻车——正是你的 Codex 团队要刻进流程里的反面教材：新服务没过安全检查不上生产、内部接口不信任本机调用、密钥泄露按"已泄露"处理而不是按"可能没事"处理。另外注意：出事的是 Phala 的托管部署，不是 DeepSeek 模型本身；DeepSeek V4.1 Flash 是你便宜档的主力模型，模型没问题，选托管方时要看对方的安全控制。

## 三、今日好用开源技能

### 1. vercel-labs/agent-browser——给 agent 的浏览器 CLI：从 shell 一条命令开网页、读页面、按编号点按，不靠截图猜像素，还能当 MCP 服务器（今日核实 54,078 star）

- **一句话能力**：一个 Rust 写的原生浏览器 CLI，让 AI agent 从 shell 一步步开浏览器：`snapshot` 把页面读成带编号（@e1、@e2）的无障碍树，agent 按编号点按/填表/截图/下载，每步做完再读一遍验结果——agent 不靠猜像素点网页；还能 `agent-browser mcp` 起一个 stdio MCP 服务器，接进任何 MCP 客户端。
- **为什么现在推**：今天直接打开 GitHub 仓库核实：Apache-2.0，**54,078 star、3,775 fork、900 次提交、124 个 release**；2026-01-11 建仓；本周 skilld.dev 周趋势在列（skilld 称 46.1k star，为旧口径，以今日仓库页 54,078 为准）。仓库自带 `skills/agent-browser` 技能，CLI 自带 `agent-browser skills get core` 拉取与当前版本同步的用法说明，装一次 stub 即可，不怕技能文档与 CLI 版本脱节。
- **安装 / 获取**：https://github.com/vercel-labs/agent-browser ；`npm install -g agent-browser` 后 `agent-browser install`（首次下载 Chrome for Testing 一次即可；Homebrew 可用 `brew install agent-browser`）；技能：`npx skills add vercel-labs/agent-browser`；MCP 服务器：`agent-browser mcp`。
- **适用工具**：Claude Code / Codex / Cursor 等任何能跑 shell 的 agent + 各 MCP 客户端；macOS / Windows / Linux 均有原生二进制。
- **一句话上手要点**：先跑 `agent-browser open <你的工具箱页面地址>` 再 `agent-browser snapshot -i`，让 agent 按 @e1 这类编号点按——拿工具箱 GitHub Pages 的部署验收练手最合适：开页面、读元素、点链接、截对比图，比截图猜坐标稳得多。
- **⚠️ 权限提醒**：它能真实点按、填表、上传、读写 cookie 与 storage，跑的是你本机 Chrome；先看 README 里的 Security 一节（auth vault、域名白名单、操作策略与内容边界），别让它在已登录账号的页面上乱点，尤其别碰支付、删库类操作。注意与 11 月 10 日推过的 Vercel agent-desktop（整机操作 CLI）是两款产品，别装混。
