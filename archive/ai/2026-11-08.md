### 1. Apiiro：Claude Code "Don't Ask Again" 把密钥写进公开仓库（11 月 5 日研究，11 月 7–8 日出圈）——今天最该先自查的一条
- **含义**：让 Claude Code 查数据库、调 API 时，它提议的命令常带着你配置里的密码或 token；点一次 "Yes, and don't ask again"，这条完整命令（含密钥原文）就以 allow 规则存进项目里的 `.claude/settings.local.json`。这个文件本应只留在本机，但它没有任何机制保证不被提交——一旦随代码推上公开仓库，任何人都能读到。
- **数字（Apiiro 口径，未独立复现）**：11 月 1–3 日扫 GitHub 公开仓库，104,185 份 `.claude/settings.local.json` 里 1,122 份（1.1%）含真实密钥，共 1,379 个不同密钥（636 个厂商格式 key + 743 个指向公开主机的密码/token）；再算上 git 历史、团队共用的 `settings.json`、存进仓库的 agent 对话记录，总数 **2,539 个密钥、1,994 个仓库、63 家机构**。其中 379 个数据库密码、**122 个 Supabase service_role key**、43 个 SSH 登录凭证（含服务器 root 密码）、42 个 GitHub/GitLab/npm token、23 个 AWS key；另有一家数据库厂商自己的管理级云 key、一个生产环境 Azure Postgres 密码、一个 Square 生产 token、一家医疗记录数据库的 owner 密码。
- **为什么防不住**：Claude Code 文档里的防护是"首次在 git 仓库里写这个文件时，把它加进开发者本机的全局 git 忽略列表"——规则不进项目自己的 `.gitignore`，所以换台机器 clone、文件夹事后变成仓库、文件早已提交过，三种情况全都漏；中位泄露仓库里，这个文件首次提交距 11 月 2 日快照已有 217 天；1,105 个可追溯仓库里 539 个有 Claude 联合署名的提交改过这个文件；常用扫描器也拦不住——1,122 份里 gitleaks 只报 564 份、TruffleHog 643 份，215 份（19.2%）两个都不报，因为密钥是嵌在命令里的密码、不是标准 key 格式；211 个 fork 连带带走了同样的密钥。
- **边界（必须同时写）**：Apiiro 没有测试任何一个凭证是否有效，"真实密钥"指格式匹配或指向公开主机、不是"已证实可用"，唯一证实是一家被通知的公司确认自己的 key 当时还有效；2,539 的总数含 LLM 评审的判断，未经第三方复现；Apiiro 自己卖 coding agent 安全产品，有利益相关；截至 11 月 8 日，Anthropic 对此研究无公开回应——GitHub 上自 2025 年 8 月起已有 4 起同类 issue 报告，无一得到 Anthropic 回复，其中 3 起被自动关闭；Apiiro 强调这是 Claude Code **产品**的行为、不是模型行为（Opus 5.5 与 Fable 5.1 均可复现），在对比的 16 个 coding agent 里，Claude Code 是唯一确认默认把完整批准命令写进项目文件的。
- **为什么出圈**：一周内第二起直冲你工具链的安全事件（上一件是 10 月 29 日 Cursor 毒扩展，11-06 日报已报）；和昨天刚讲的 Claude Code 2.1.319 `denyInsteadOfPrompting` 连起来读——无人值守跑批最缺"不卡住"的开关，但 allow 规则一旦写进文件，跑批的便利和泄露的风险是同一枚硬币的两面。
- **与你的关联（先做这三件事）**：① 你有 Supabase 账号——如果你或合作方曾在 Claude Code 命令行里贴过 service_role key，立即去 Supabase 后台轮换，顺手查你参与的公开仓库有没有 `.claude/settings.local.json` 被提交；② 所有项目补一行项目级 `.gitignore`：`**/.claude/settings.local.json`（别只依赖本机全局忽略），再用 `git log --all -- .claude/settings.local.json` 查历史，提交过的先轮换密钥、再清历史；③ 以后别把密钥贴进命令本身——走环境变量或 gitignored 的 `.env`，让 agent 读变量名而不是密钥值。另注意团队共用的 `.claude/settings.json` 里也查出 298 份含密钥（76,011 份里），共享配置一样要审。
- 出处：Apiiro 研究 2026-11-05（作者 Shmulik Cohen、Matan Giladi），经 https://madrobot.blog/2026/11/07/claude-code-dont-ask-again-secrets-github/ · https://cybersecuritynews.com/claude-codes-yes-and-dont-ask-again/ · https://pasqualepillitteri.it/en/news/31165/claude-code-leaks-passwords-api-keys-github-apiiro 转述核对

### 2. Vals CyberOffense：开源权重追到只差 8 个点，成本十分之一（11 月 6–7 日报道）——"能力被管住"之后，"权重管不住"
- **含义**：Vals 的 CyberOffense 基准把每个模型放进隔离 Kali 机里的开源 Pi agent，只给一个公开网址、零人工帮助，去打两个模拟企业内网。OpenAI 受限 Daybreak 项目里的 GPT-6 Sol 完成 80.8% 的攻击目标、排第一；任何人都能下载的开源权重 DeepSeek V4.1 Flash 1017 完成 72.8%，单次成本约 $3、对 GPT-6 Sol 的约 $22。
- **细节**：简单网段 Nova（21 个目标）DeepSeek 反而领先，平均 16.3 对 15.7；更难的 Lighthouse（31 个目标、要拿下一家公司再用偷到的密码打第二家）Daybreak 27 个、不到 3 小时，DeepSeek 21 个；同场其他模型 Lighthouse 成绩：Meta Wonder 28、Kimi K3.1 Pro 20、Grok 4.7 16、Kimi K3 10、GLM 5.3 Flash 5。DeepSeek 前 2,500 万 token 一分不得，大部分进展在 1 亿 token 之后——短评测会系统性低估便宜的开源模型。
- **背景**：英国 AI 安全研究所 7 月分析：开放与闭源在网络能力上的差距已缩到 4–7 个月（2025 年大部分时间是 6–10 个月）；该所估算一次网络靶场 run，DeepSeek V4-Pro 约 $1.19、Anthropic Opus 4.5 约 $85。
- **为什么出圈**：11 月 5 日 OpenAI 刚把 GPT-6 Cyber 定为 Critical 级、锁进 Daybreak Red 门禁（11-06 日报主线），两天后基准就证明"被锁起来的能力，开源权重已经会了七成多、还便宜一个数量级"；Vals 预计真实网络攻击未来数月会增加——同一批模型既能帮防守方先找漏洞，也能帮攻击方。
- **与你的关联**：你玩开源权重、审代码、搭 agent——"开源权重 ≈ 受限旗舰的网络能力"意味着以后评估任何 agent 工具链，都要默认攻击侧也有同等能力；Kimi K3.1 Pro（11-07 日报主线）在 Lighthouse 拿 20 个目标，也值得记一笔：它不只是"开放权重旗舰"，也是"开箱即用的攻击侧模型"。
- 出处：https://the-decoder.com/the-gap-between-open-and-closed-ai-models-in-cyber-capabilities-keeps-shrinking/（2026-11-07）· https://pivotnews.ai/five/open-weight-models-trail-closed-rivals-by-eight-points-in · https://paktechstan.com/article/free-deepseek-model-nearly-matches-openai-s-restricted-cyber-ai-at-hacking-corporate-networks

### 3. 高盛把 Claude Code / Copilot 收回工程师手里（11 月 2 日 Bloomberg，补报）——vibe coding 的第一次大回潮
- **含义**：高盛 10 月更新内部指引，Claude Code 与 GitHub 编码工具只给约 12,000 名工程师与 "strats"（量化 + 写生产代码的混合岗），用这些工具看了几个月客户资金流、建仓模型、写图文材料的交易员与投行家被收回权限。发言人 Nick Carcaterra 口径："一段实验期"后按"生产力与风险管理等多方面因素"评估，交给"最适合长期使用的人"。

- **对照**：BNY 反其道而行，让非工程师在自家 Eliza 平台（按银行数据与合规要求设计的环境）里继续搭；三菱 UFJ 发现 Claude Code 能绕过其信息访问限制后自研了内部替代品；德意志银行与高盛同款做法——只给专业开发者。

### 4. Google 学校政策：不要 AI，就没有搜索（11 月 3 日官宣，补报）——"AI 正在变成基础设施的默认层"
- **含义**：Google 宣布 K-12 学生账号上 Gemini、Gemini Notebook、Gemini in Classroom、Google Search 四项全部默认关闭，管理员显式打开才可用；学校可以单独开 Gemini、Notebook、搜索中的一项或几项，但**没有"无 AI 的搜索"**——搜索本身已集成 AI Mode 与 AI Overviews，彻底拒绝 AI 的学校，学生账号也失去搜索。教育副总裁 Chris Phillips 原话："search and AI are deeply integrated"。
- **时间**：纽约时报口径，控制项 2027 年初生效；Google 称"未来数月"公布更多实施细节；Search 里的 Guided Learning（把作业题拆成步骤带学生做、不直接给答案）本月内在部分美国学校试点。背景：8 月 Google 把 Gemini 默认开给 K-12 课堂后遭教育界反弹，纽约、洛杉矶等大学区今年已临时禁生成式 AI；Common Sense Media 7 月给 Google 的 AI 搜索功能打了最低档"不可接受风险"。
- **与你的关联**：NotebookLM 在你的全景表里——它正在从"好用的研究助手"变成学校默认基础设施的一部分，opt-out 的代价是失去基础服务；这个"不接受 AI 就失去基础功能"的捆绑写法，以后在别的厂商那里还会出现，记下来当判据。
- 出处：https://www.cnn.com/2026/11/03/tech/google-ai-search-policy · https://www.medianama.com/2026/11/223-google-schools-switch-off-gemini/ · https://economictimes.indiatimes.com/tech/artificial-intelligence/google-will-cut-off-search-access-for-students-at-schools-that-reject-ai/articleshow/135519447.cms

### ① google/skills（Google 官方）：官方技能库的范式之作，本周热度再起
- **一句话能力**：Google 官方的 Agent Skills 仓库——190 余个 SKILL.md，覆盖 GCP 上手、GKE、BigQuery、Cloud Run、Firebase、Gemini API、gcloud CLI、Well-Architected 六大支柱、SecOps 等；agent 按官方流程做 Google Cloud 与 Gemini 相关工作，不用靠记忆瞎编参数与命令。
- **为什么今天推（本周再热，非今日首发——日期说清楚）**：仓库创建于 2026-03-31，Cloud Next '26 上发布，今日核实 23,646 stars、1,973 forks、552 commits（11 月 6 日 22,626 stars，两天涨约 1,000）；本周多家周报把它列为本周五大 AI 动态之一。推它的理由不是"新"，是你正在搭 Codex 团队、给"资料官"定"预整理资料包"的做法——google/skills 就是"官方亲自下场、把自家产品知识预整理成 agent 可直接用的技能包"的标杆：按产品分目录、每个技能配工作流与护栏、还能 `npx skills update` 统一更新。
- **安装 / 获取来源**：https://github.com/google/skills（Apache 2.0）。`npx skills add google/skills`（按提示选技能、目标 agent、全局或项目级安装）；插件市场：Claude Code 用 `claude plugin marketplace add google/skills` 后 `claude plugin install <plugin>@google-plugins`，Codex 同理；另有 Antigravity CLI 插件。需 Node.js（含 npx）。
- **适用工具**：Claude Code / Codex / Antigravity CLI（插件）；SKILL.md 通用格式，其他兼容 agent 也可直接读。
- **一句话上手**：先只装 `gcloud` skill（强制先查叶子级 `gcloud help` 再规划命令、禁网搜猜参数、带拒绝列表与 dry-run）与 BigQuery Basics 两个，按需再加；`npx skills update` 保持更新。
