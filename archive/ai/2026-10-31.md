## 一、新词 / 出圈内容

### 1. `__usage_ai-training`：四家大厂共认的"AI 训练退出"暗号
- **含义**：写在网站 robots.txt 里的一行"政策 token"，不是爬虫名。写法（IETF 草案示例）：
  ```
  User-Agent: __usage_ai-training
  Disallow: /
  Allow: /press-kit/
  ```
  意思是：整站内容不许用于 AI 训练，但 `/press-kit/` 例外。以前要达到同样效果，得给每家各写一组规则（Google-Extended、GPTBot、ClaudeBot……），现在一句顶四家。
- **来源（10 月 30 日，四方同日表态）**：Anthropic 标准负责人 Kevin Kelley 起草的 IETF 个人草案 `draft-kelley-aipref-training-preference-signal-00`（10 月 30 日提交，2027 年 5 月 3 日到期）；Google（Search Central 博客，John Mueller）、微软（Bing 博客）、OpenAI（政策页）同日承诺遵守；Anthropic 称已开始实现。注意：**这只是个人草案、尚未成为 IETF 正式标准**，四家是"先承诺、后标准"。
- **为什么出圈**：四个直接竞争对手同一天认同一个写法，极为罕见；背景是出版商长期抱怨"每家一个暗号"，以及欧盟《通用 AI 行为准则》把 robots.txt 视为表达机器可读偏好的主要方式。Meta 和 Apple 不在承诺名单里——Meta 只出现在草案致谢名单中，未承诺读这个 token。
- **四个容易踩的坑（按草案原文与各家公告区分，别想当然）**：
  1. **不是"禁止爬取"**：它只表达"用途偏好"（不许改模型参数式训练），不拦爬虫、不影响搜索收录；想让爬虫别来，仍要写针对爬虫名的规则。
  2. **`User-Agent: *` 不算数**：草案明确规定通配符组不得解释为匹配该 token；没写这行就等于"没表达偏好"。旧的 Google-Extended 屏蔽也不自动等同于这个共享信号。
  3. **不追溯既往**：偏好按"内容被抓取时"的 robots.txt 算，已经抓走的内容不受新行影响。
  4. **私人协议优先**：有内容授权协议的，按协议走，不被这行推翻。
- **生效时间各不相同（公告日 ≠ 生效日）**：微软 2027 年 2 月 1 日起按抓取执行，并同时停读旧的 NoArchive / NoCache 标签（2027 年 3 月 1 日后不再作为训练/ grounding 偏好；Bing Webmaster Tools 过渡设置 2026 年 12 月 15 日开放、2027 年 9 月 30 日过期）；Google 目标 2027 年初；OpenAI 只说"未来几个月"，未给日期；Anthropic 已开始实现、未给上线日期。
- **Google 与微软的分歧，选边前必看（PPC Land 对公开文档的梳理，非 Google 官宣原话）**：微软把"训练"和" grounding（回答时引用网页）"分开管——训练用共享 token，grounding 另有页面级设置（含 DisallowExtended：只许微软自家 Copilot 等引用、不许卖给第三方 grounding 服务）。Google 则把共享 token 映射为 Google-Extended，而 Google-Extended 同时管训练和 grounding——于是**在 Google 这边，写共享 token 退出训练，顺带也退出了 Gemini 回答里的引用**；想"不许训练、但要 Gemini 引用"，Google 目前没有单一设置，只能再单写一条明确允许 Google-Extended 的组来覆盖。微软还警告：选 grounding 限制会降低在 AI 回答里的可见度，且"不保证收录、流量或付费"。
- **与你的关联**：你若有公开内容站/博客/作品页，今天就可以先把这行加上（零成本、向前兼容），但**别急着删旧规则**——今天没有任何一家真正开始读它，旧的各家 token 仍是唯一生效的防线；2027 年 2 月微软切换前再复查一次。反过来，你用 agent 抓公开数据做训练/微调时，这行就是未来要遵守的"数据红线"信号：合规抓取要先读 robots.txt 的这组，而不只是看爬虫放行与否。

### 2. OpenAI 青少年安全新规 + Community Safety Report（10 月 30 日，路透）
- **含义**：ChatGPT 青少年体验再收紧，并承诺定期公开安全报告。不是新模型、新功能，是治理层面的产品规则变化。
- **具体变化（OpenAI 10 月 30 日公告，经路透转述）**：
  - 青少年：即使问题看起来无害，也要限制"可被滥用的武器与安防系统实操信息"；仍可用于预防、降级冲突、求助、联系可信成年人。
  - 所有用户：减少对过往大规模袭击细节的描述（用过什么武器、怎么获得的）；对话出现"执着于暴力"迹象时可自动结束对话，多次出现可临时暂停账号。
  - 年龄预测加强：持续评估信号，把估计未满 18 岁的用户移入青少年体验；误判的成年人可经 Persona 验证解除；正在推进"青少年账号因反复谈论暴力被暂停时通知家长"。
  - 数字（厂商自报，经路透转述）：2026 年 Q3 向执法部门转介 200 多起；青少年日均使用 ChatGPT 不足 15 分钟（10 月初首份青少年使用报告口径）。
  - Community Safety Report：首份定于 2027 年初发布，覆盖 2026 年下半年，此后每半年更新，主题为暴力预防与其他社区安全及保障措施效果。
  - 生效节奏：未来几周内开始滚动上线，不是 10 月 30 日当天全部生效；自动中断对话、暂停账号等被描述为"持续推进的工作"，不是已全量上线的功能。
- **为什么值得记**：这是 10 月"厂商治理层"续集的第三棒——10 月 29 日 Model Spec 五价值重写 + 失齐监测公开，10 月 30 日就接上青少年安全与定期报告。治理正在从"内部文档"变成"对外可核查的节奏"（半年一报），以后评估一家厂商的安全承诺，可以看它按期交了什么报告，而不只看它说了什么。
- **与你的关联**：直接影响有限（你不是青少年用户），但有两个参照点：① 家里青少年用 ChatGPT 时，青少年体验的边界在收紧，误判成年人进青少年体验时有 Persona 验证路径；② 你给 agent 定规则时可借鉴这个"分层"思路：对高风险话题不是一刀切禁言，而是"限制实操细节、保留求助通道、多次触发才暂停"。

### 3. 多智能体时代的配套一对：Rulesync 10 月 30 日更新 + "密钥别跟着配置一起同步"的警告
- **Rulesync 是什么**：开源 CLI（MIT），用一份 `.rulesync/` 统一规则源，生成各家编码智能体的配置文件——规则、MCP、命令、子智能体、技能、hooks、权限一次写好，不用给 Claude Code、Codex CLI、Cursor、Kimi Code、Antigravity 等各维护一份。仓库已直接核实：公开、MIT、1,569 星、8,189 commit、2025 年 6 月建仓，支持表里含 Claude Code / Codex CLI / Cursor / Kimi Code / Antigravity IDE 与 CLI 等数十个目标。
- **10 月 30 日更新 43.4.0（转述口径，UNDERCODE NEWS）**：重点在兼容性与安全默认值——Crush 的 hook 事件映射补齐（12 个标准事件，如 beforeSubmitPrompt → TurnStart）；ZCode 上把标准 `failClosed: true` 翻译成其原生 `onError: "deny"`（hook 出错默认拒绝、而不是放行）；Kimi Code 2.4.0 的 MCP 重连退避配置；OpenCode 2.x 迁移适配。关键词就一个：**fail-closed**——安全 hook 挂了就拦住，别悄悄放行。
- **同一天的反向警告（Stackness 10 月 30 日分析文章，非厂商公告）**：2026 年 10 月确认的编码智能体用户密钥泄露，走的不是 `.env`，而是**项目里的 agent 配置文件本身**：GitGuardian 统计 2025 年公开 GitHub 上 MCP 配置文件里有 24,008 个唯一密钥；LiteLLM 复盘链条是 5 月 27 日有人把含内部管理密钥的 `opencode.json` 提交到公开仓、3 小时后删文件但密钥未吊销、10 月 10 日被攻击者利用、10 月 21 日恶意 `litellm==1.107.0` 上 PyPI；另有 Railway 10 月 20–22 日事件（厂商披露：不超过 1.85% 工作区受影响）与 OpenCode Console 10 月 16 日事件（厂商称影响 1.4% Console 用户，CLI 本地密钥不受影响）。
- **给你的三条可直接做的事**：
  1. 配置里只写引用、不贴密钥：OpenCode 用 `{env:VAR}`、`.mcp.json` 用 `${VAR}`、Cursor 的 `mcp.json` 用 `${env:NAME}`、Codex 用 `bearer_token_env_var`、Claude Code 自家 key 用 `apiKeyHelper`。
  2. 凡是进过公开仓的密钥只做一件事：**在厂商处吊销**，删文件、删 commit 都不算数（历史还在）。
  3. 自查两条命令：`git ls-files | grep -E '(opencode\.jsonc?|\.mcp\.json|mcp\.json|settings(\.local)?\.json|config\.toml|auth\.json)$'` 看哪些 agent 配置被 git 跟踪；`gitleaks git -v --redact --log-opts="--all" .` 扫全部历史；再给每个 key / 工作区设硬性 spending cap（OpenAI、Anthropic、Google Cloud、OpenRouter 均有硬上限口径，唯 OpenRouter 能按单个 key 设；AWS Bedrock 没有原生硬上限，只有预算动作）。
  - 注意剔除：该文提到的 10 月 10 日约 $88,982 谷歌云账单、"Codex 把 .env 发到 Cloudflare Pages"的说法，作者自己标注为**未证实诊断**，今日不采信为事实。
- **与你的关联**：你同时用 Claude Code / Codex / Cursor 这类工具，Rulesync 正好解决"规则改一处、处处同步"的重复劳动——但同步的是规则，**不是密钥**：先用上面第 1 条把密钥改成引用，再开同步，否则 Rulesync 会把一个工具的密钥配置原样扩散到所有工具的配置文件里。仓库根目录自带 `.secretlintrc.json`，也是个提醒：同步工具本身都在防密钥进仓。

## 五、今日好用开源技能

### ① Rulesync：给所有编码智能体只写一份规则，改一处、处处同步
- **一句话能力**：一份 `.rulesync/` 规则源，生成 Claude Code、Codex CLI、Cursor、Kimi Code、Antigravity 等数十个工具的规则 / MCP / 命令 / 技能 / hooks / 权限配置，解决"换个工具就得重写一遍 CLAUDE.md / .cursor/rules / AGENTS.md"的重复劳动。
- **为什么今天推**：10 月 30 日刚更新 43.4.0（转述口径），补齐 Crush hook 事件、ZCode fail-closed 翻译、Kimi Code MCP 重连——正好是你多工具并用的痛点；且它与今日密钥泄露警告是同一枚硬币的两面：同步规则前，先把密钥改成环境变量引用（见主线第 3 条）。
- **安装 / 获取来源**：https://github.com/dyoshikawa/rulesync（已直接打开仓库核实：公开、MIT、主分支含 `skills/rulesync`）。`npm install -g rulesync`，然后 `rulesync init` 生成示例，再 `rulesync generate --targets "*" --features "*"`；已有配置的先 `rulesync import --targets claudecode`（从 CLAUDE.md 导入）再生成给其他工具。
- **适用工具**：Claude Code、Codex CLI、Cursor、Kimi Code、Antigravity IDE/CLI、Copilot、OpenCode、Crush、ZCode 等（仓库支持表数十个目标；注意各目标支持的功能列不完全相同，生成前先看支持表）。

- **安全提醒（必读）**：Rulesync 会读写各工具的配置文件并可拉取外部规则/技能源——**配置文件里绝不要放明文密钥**，一律用环境变量引用；从外部仓库 `fetch` 规则/技能前先看源仓库内容，钉住版本再装；它生成的 hooks 会实际拦截/放行你的操作，`failClosed` 类配置改动后先在小项目里验证。
